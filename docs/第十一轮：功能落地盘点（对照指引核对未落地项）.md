## 三、挑一处深挖："驾驶舱口径对齐监测指标体系" 是不是空头支票

第 29 项驾驶舱声称"11 项指标卡口径对齐《监测指标体系（2024 版）》"。
这类"对齐某标准"的话最容易挂着好看却是空的，重点查。

- **不是空的**：`/api/metrics/overview` 返回的每个字段都是真汇总
  （促分工基层诊疗占比、同质化远程诊断量与互认率、双向转诊、集中审方、
  慢病管理、库存预警），代码里逐项标注对应的监测指标号（4/5/7/8/13）。
- **有测试撑**：`test_modules` 播种数据后断言
  `grassroots_encounter_ratio_pct == 100.0`、`recognition_ratio_pct == 50.0`
  ——指标随数据真的动，不是返回零占位。

**一处如实标注的边界**：代码里显式追到指标号的只有 4/5/7/8/13 这几条。
"11 项指标卡全部对齐 2024 版指标体系" 这句要做到逐条可验，需要那份指标体系
的权威条目清单来点对点核对——手头没有这份清单，**既不能宣称全对齐，也不能
凭空说缺了几条**。按前几轮的口径，这属于"断言成立但未逐条追溯"，
如实标注，不假装已核。要做这一步，需要先拿到《监测指标体系（2024 版）》原文。

## 四、真正仍开口的——都是环境依赖，不是功能缺失

这四条每一轮都如实登记，此轮复核仍在，且仍不做——理由不是没排上，
是**没有真实环境验证就改了也不知道对错，宁可不写"已支持"**：

| 项 | 现状 | 为什么不做 |
|---|---|---|
| 信创国产库适配 | 从未在达梦/人大金仓/麒麟跑过迁移 | 没有国产库环境，跑不了就不写"已适配" |
| 国密 SM2/SM4 | JWT 用 HS256、口令 PBKDF2；已实现纯 Python SM3 | 不自己实现 SM2/SM4 密码算法；接密码机是部署期对接 |
| 金额端到端 Decimal | `asdecimal=False`，Python 侧仍 float | 没有真实医保结算场景，改了验不出对错，留待同批做 |
| DICOM 阅片/波形分析 | 报告图文闭环用 `attachments` | 阅片器/波形算法是 PACS/心电设备职能，不做玩具版 |

## 五、这一轮做了什么、没做什么

- **做了**：把第七轮的子功能待补清单逐条拿代码复核，确认无一遗漏；
  深挖一处"对齐标准"的断言，确认不是空头支票、但如实标出它未逐条追溯的边界。
- **没做**：没有为了"再交付点什么"去动那四条环境依赖项——它们不是拖着没做，
  是做了也无法验证。硬做只会得到一版"看起来支持、实则没测过"的东西，
  那正是这几轮一直在拆的那种假完成。

**盘点结论：功能条目无未落地项；开口的都是环境依赖，需真实环境/权威清单才能
继续，不在无输入的情况下假装推进。**
