# 县域医共体信息化平台 接口对接规范（V1.0）

> 面向对象：医共体成员单位 HIS/LIS/PACS/公卫系统厂商，以及省/市全民健康信息平台对接方。

## 一、对接总则

1. **传输协议**：HTTPS + JSON（UTF-8）。生产环境经电子政务外网/卫生健康专网访问，禁止公网直连。
2. **身份认证**：对接方使用平台开通的系统账号调用 `POST /api/auth/login` 换取 Bearer 令牌（有效期8小时），全部业务接口携带 `Authorization: Bearer <token>`。
3. **编码要求**：诊断按 ICD-10、药品/耗材/收费按平台"四统一"字典（`/api/dictionaries/{system}/entries` 可下载对照）。对接前须完成本地编码到平台编码的映射。
4. **患者标识**：一切业务数据以平台患者主索引为准。推送数据前先调用 `POST /api/patients`（按身份证号幂等）取得 `patient_id` 与电子健康卡号 `ehc_no`。
5. **幂等与重试**：网络异常按指数退避重试；平台侧对患者建档、慢病建档、字典导入等接口保证幂等。
6. **审计**：所有写操作平台自动留痕（操作账号、接口、时间、结果），对接方应使用专属系统账号，禁止共用。

## 二、核心资源与 FHIR R4 映射

平台资源模型与 HL7 FHIR R4 的对应关系（用于与省平台或第三方按 FHIR 交换时的转换基准）：

| 平台资源 | 接口 | FHIR R4 资源 | 关键字段映射 |
|---|---|---|---|
| 患者主索引 Patient | `/api/patients` | Patient | ehc_no→identifier(EHC), id_card→identifier(national ID), name→name, gender→gender, birth_date→birthDate |
| 机构 Organization | `/api/organizations` | Organization | org_type/level→type, parent_id→partOf |
| 就诊记录 Encounter | `/api/encounters` | Encounter + Condition | encounter_type→class, diagnosis_code→Condition.code(ICD-10) |
| 检查检验申请 ExamRequest | `/api/exams` | ServiceRequest | center_type→category, item_code→code, clinical_info→reasonCode.text |
| 检查检验报告 ExamReport | `/api/exams/{id}/report` | DiagnosticReport | conclusion→conclusion, critical→flag(危急值), finding→presentedForm |
| 处方 Prescription | `/api/prescriptions` | MedicationRequest | items[].drug_code→medicationCodeableConcept, daily_dose/days→dosageInstruction |
| 双向转诊 Referral | `/api/referrals` | ServiceRequest(referral) | direction/from/to→requester/performer, status→status |
| 远程会诊 Consultation | `/api/consultations` | Communication/ServiceRequest | question→reasonCode.text, opinion→note |
| 慢病档案 ChronicPatient | `/api/chronic` | CarePlan + Condition | disease→Condition.code, level→CarePlan.status扩展 |
| 随访 FollowUp | `/api/chronic/{id}/followups` | Observation | sbp/dbp→85354-9(LOINC), glucose→2339-0 |
| 传染病报告 InfectiousCase | `/api/infectious/cases` | Condition + Communication | disease_code→code, onset_date→onsetDateTime |
| 家医签约 Contract | `/api/contracts` | CarePlan/Contract | package→Contract.term, services→CarePlan.activity |
| 预约 Appointment | `/api/appointments` | Appointment + Slot | slot→Slot, status→Appointment.status |

## 三、典型对接流程

### （一）HIS 推送就诊数据（诊间同步）

```
1. POST /api/auth/login                      → 取令牌
2. POST /api/patients                        → 取 patient_id（幂等）
3. POST /api/encounters                      → 推送就诊摘要（诊断须为 ICD-10 编码）
4. （慢病患者）POST /api/chronic             → 建档（幂等）
   POST /api/chronic/{id}/followups          → 诊间随访数据（血压/血糖）
```

### （二）基层检查、上级诊断（LIS/PACS 协同）

```
1. GET  /api/exams/recognition-check?patient_id=&item_code=   → 互认检查
2a. 可互认且患者同意 → POST /api/exams（accept_recognition_of=既往申请单id）
2b. 不互认 → POST /api/exams（recognition_declined_reason 必填，监管留痕）
3. 中心端（医师角色）POST /api/exams/{id}/claim → /report
4. 危急值：GET /api/exams/critical 轮询或由平台推送（预留 webhook）
```

### （三）处方全量上传集中审方

```
1. POST /api/prescriptions        → 系统审即时返回 auto_passed / pending_review
2. pending_review 的处方由药师角色 POST /api/prescriptions/{id}/review
3. HIS 侧凭 status 控制发药：auto_passed / approved 可发药，rejected 禁止
```

## 四、错误码约定

| HTTP 状态码 | 含义 | 对接方处理 |
|---|---|---|
| 401 | 令牌缺失/过期 | 重新登录换取令牌后重试 |
| 403 | 账号角色无权限 | 检查系统账号角色配置，联系平台管理员 |
| 404 | 引用的资源不存在 | 检查 patient_id/org_id 等外键是否先行创建 |
| 409 | 业务冲突（重复、状态不允许、库存不足） | 按返回 detail 提示处理，勿盲目重试 |
| 422 | 字段校验失败 | 按返回 detail 修正报文 |

## 四之一、列表分页与日期参数约定（第四阶段 L 系列整改）

### 分页（L-3/上轮 L4）

高频列表接口（患者检索 `GET /api/patients`、就诊 `GET /api/encounters`、检查申请 `GET /api/exams`、
处方 `GET /api/prescriptions`、慢病 `GET /api/chronic`、结算 `GET /api/insurance/settlements`、
审计 `GET /api/audit` 等）统一支持：

- 查询参数 `offset`（默认 0）与 `limit`（默认值与原接口上限一致，最大 500）；
- 响应头 `X-Total-Count` 返回过滤条件下的总记录数，供前端计算页数；
- 不传分页参数时行为与既往版本完全兼容。

### 日期参数（L-2/上轮 L3）

预警/超期类接口（`/api/chronic/overdue`、`/api/medwaste/alerts`、`/api/infectious/alerts`、
`/api/exams/critical/unacknowledged`、`/api/publichealth/reminders/{id}` 等）的基准日期
由**服务端注入当前日期**。`today` 覆盖参数（YYYY-MM-DD，格式非法返回 422）**仅限测试
与管理排查用途**，生产对接方不得传入，平台不保证其长期保留。

## 五、安全要求

1. 系统账号密码定期轮换（`POST /api/auth/change-password`），最小权限分配角色；
2. 传输层 TLS ≥1.2；生产环境部署国密改造后按国密套件协商；
3. 涉及居民隐私字段（身份证号、电话）不得落地于对接方日志；
4. 对接方系统须通过等保测评后方可接入生产环境。

### 附录B：敏感数据脱敏口径（第三阶段 H1 整改）

- 公共脱敏模块 `server/app/privacy.py`：身份证号保留前4后4、电话保留前3后2；
- 工作人员侧一切返回身份证号/电话的接口（患者检索/详情、FHIR/HL7 出入站、导出）非 admin 一律掩码；
- 居民本人（/api/portal/me/*）须登录并完成实名绑定后方可见本人档案（见附录C）；
- 新增接口必须复用公共脱敏模块，禁止各自实现。


### 附录C：居民端身份体系（手机号验证码 / 微信登录）

居民端不再用"电子健康卡号 + 身份证号"直接查档案（居民记不住卡号，且那是一个
免登录的证件号查询面）。改为账号体系，三步走：

| 步骤 | 接口 | 说明 |
|---|---|---|
| ① 取验证码 | `POST /api/portal/auth/sms/code` | body `{phone, purpose}`；三重限流：单号冷却60秒、单号10分钟5条、单IP10分钟20条 |
| ① 验证码登录 | `POST /api/portal/auth/sms/login` | body `{phone, code}`；首登自动开户 |
| ① 微信授权 | `GET /api/portal/auth/wechat/authorize` → `POST /api/portal/auth/wechat/login` | 返回授权页地址；mock 通道额外返回 `mock_code` 供无公众号环境走通全流程 |
| ② 实名绑定 | `POST /api/portal/auth/realname` | body `{name, id_card}`；一份档案只允许一个账户绑定（409），失败按账户计数锁定10分钟 |
| ③ 查档案 | `GET /api/portal/me/archive` | 仅带令牌，客户端不再传任何身份标识 |
| ③ 提交评价 | `POST /api/portal/me/surveys` | 同上 |
| — | `GET /api/portal/me` | 账户信息，手机号按 privacy 口径脱敏（前3后2） |
| — | `POST /api/portal/auth/bind-phone` / `bind-wechat` | 两种登录方式互绑到同一账户 |
| — | `POST /api/portal/auth/logout` | 按 jti 拉黑令牌（与业务端共用黑名单） |

约束与要点：

- **登录 ≠ 可见档案**。登录只证明手机号/微信归属，未实名绑定的账户访问
  `/me/archive` 返回 403，只能看健康宣教。
- **手机号自动绑定的边界**：登录手机号在患者主索引中**唯一**命中时自动完成实名
  绑定；命中多条（全家共用一个号）时不猜，退回显式实名绑定。
- **令牌互不越界**：居民令牌带 `scope=portal`，业务端 `get_current_user` 见到即
  401；业务端令牌无该 scope，`current_resident` 见到也 401。
- **验证码**只落 PBKDF2 散列、一次性消费、单条最多试错5次；连续失败5次锁号10分钟。
- **debug_code**：仅当短信通道为 `console` 且 `environment != prod` 时在下发响应中
  回显，供本地联调与演示站使用；生产环境永不回显。
- **通道适配**：短信见 `server/app/sms.py`（console / http 网关），微信见
  `server/app/wechat.py`（mock / 公众号网页授权），由 `MEDPLAT_SMS_PROVIDER`、
  `MEDPLAT_WECHAT_PROVIDER` 选择，接入真实通道无需改业务代码。
- **旧双因子接口**（`GET|POST /api/portal/my-archive`、`POST /api/portal/surveys`）
  标记 deprecated 保留过渡，设 `MEDPLAT_PORTAL_LEGACY_VERIFY=false` 后返回 410，
  生产环境建议关闭。
