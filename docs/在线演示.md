# 在线演示

把这个仓库变成一个能点开就看的演示站，有三条路径。按「多快能看到东西」排序：

| 路径 | 起步动作 | 能分享给别人 | 数据持久 | 适合 |
|---|---|---|---|---|
| **GitHub Codespaces** | 仓库首页 → `Code` → `Codespaces` → `Create codespace` | 需手动把 8000 端口改为 Public | 否（Codespace 删掉即止） | 最快，本机什么都不用装 |
| **Render 蓝图** | README 的 `Deploy to Render` 按钮 | 是，给一个固定域名 | 否（免费档无持久盘，重部署即重置） | 给别人一个能收藏的地址 |
| **本地 docker compose** | `docker compose up` | 否（局域网内可） | 是（命名卷） | 内网/离线演示、断网现场 |

三条路径**共用同一个启动入口** `server/start.sh`：`alembic upgrade heads`（复数 head：
平台链 + spd 链）→ 起 uvicorn → 等 `/api/health` 就绪后灌演示数据。演示环境不另写一套
启动逻辑——本仓库已经因为「演示口令两处各写各的」让公网演示站空过一次，见文末排查一节。

## 一、GitHub Codespaces（一键，推荐先用这个）

1. 打开 <https://github.com/xujiann/trytry>；
2. `Code` → `Codespaces` → `Create codespace on <分支>`；
   > **分支要选对**：一键按钮与 `codespaces.new/xujiann/trytry` 都按**默认分支**建 Codespace，
   > 而 `.devcontainer/` 是随某个功能分支进来的——它还没合进默认分支时，用默认分支建出来的
   > Codespace 不会自动起演示站。此时改用 `https://codespaces.new/xujiann/trytry?ref=<分支名>`，
   > 或在 `Code` → `Codespaces` 里先切到那个分支。
3. 等约 1 分钟（装依赖 → 迁移 → 起服务 → 灌演示数据，终端里能看到全过程）；
4. `PORTS` 面板出现 8000 端口，点地球图标或 `Open in Browser` 即为管理端；
   居民端在 `/m`，接口文档在 `/docs`。

**要分享给别人看**，得先把端口从默认的 Private 改成 Public：
`PORTS` 面板里右键 8000 → `Port Visibility` → `Public`；或在本机用 gh CLI：

```bash
gh codespace ports visibility 8000:public -c <codespace-name>
```

改成 Public 后那个 `*.app.github.dev` 地址任何人可访问——**演示完记得删掉 Codespace**。

`.devcontainer/` 里只有三个文件，都很短：

- `devcontainer.json`：镜像（Python 3.12，与 CI/生产镜像同版）、演示档环境变量、端口转发；
- `setup.sh`：按 `requirements.lock` 装运行时依赖（与生产镜像同一份钉版清单）；
- `start-demo.sh`：`cd server && sh start.sh`，不自造启动逻辑。

想在 Codespace 里跑测试，再补一步开发工具：`make install`，然后 `make verify`。

## 二、Render（要一个持久的公网地址）

仓库根的 `render.yaml` 是一份 Render 蓝图（Docker 运行时、免费档）。点 README 里的
`Deploy to Render`，或手动 `New` → `Blueprint` → 选这个仓库。

部署时**必须手工填一个环境变量**：

| 变量 | 值 | 为什么要手工填 |
|---|---|---|
| `MEDPLAT_ADMIN_PASSWORD` | 自己想一个：**≥12 位、含多类字符** | 蓝图里是 `sync: false`，故意不写进仓库。曾经用 `generateValue` 自动生成，结果是没人知道口令、演示者自己登不进去 |

`MEDPLAT_SECRET` 由 Render 自动生成随机值（`generateValue: true`），不用管——但也别
删掉这条，否则会退回代码里那个人人可见的默认密钥，谁都能给自己签一个 admin 令牌。

几点要知道的：

- 免费档没有持久盘，用的是容器内 SQLite：**每次重部署/休眠唤醒数据都会重置**，
  重置后 `start.sh` 会重新灌一遍演示数据，所以演示站永远是干净的初始状态；
- 免费档实例闲置会休眠，第一次访问要等十几秒冷启动；
- 蓝图里 `branch:` 钉的是主干分支，改这里可以让演示站跟别的分支。

要长期对外的演示站，把 `MEDPLAT_DATABASE_URL` 指向一个 PostgreSQL 实例即可（此时
`MEDPLAT_SEED_DEMO` 建议关掉，别往正经库里灌演示数据）。

## 三、本地（docker compose 或直接跑）

```bash
# 方式 A：compose（贴近生产形态，PG + Redis 都在）
MEDPLAT_SECRET=... MEDPLAT_ADMIN_PASSWORD=... docker compose up

# 方式 B：直接跑（开发库 SQLite，最省事）
cd server
pip install -r requirements.txt
uvicorn app.main:app --reload          # http://127.0.0.1:8000/
python scripts/seed_demo.py            # 另开一个终端，灌演示数据
```

## 排查：演示站起来了，但一条数据都没有

先看启动日志有没有这一行：

```
⚠️ 演示数据灌入失败：服务继续运行，但演示数据为空（原因见上一行脚本报错）。
```

最常见的原因是 **`MEDPLAT_ADMIN_PASSWORD` 与实例启动时用的口令不一致**：种子脚本要以
`admin` 身份登录才能灌数据，口令对不上就 401。脚本会把具体 HTTP 状态码打出来。
（脚本读的是应用自己的配置 `app.config.get_settings()`，环境变量与 `.env` 的解析口径
与服务端完全一致，所以只要脚本和服务跑在同一份配置下就不会对不上。）

注意一个容易踩的点：`MEDPLAT_ADMIN_PASSWORD` 只在**首次建 admin 账号**时生效
（`main.py` 的种子化）。库里已经有 admin 了再改这个变量，改的只是种子脚本用来登录的
口令，账号本身的口令不会跟着变——此时要么改回原口令，要么清库重来（免费档重部署即清）。

历史上这里有过一个静默失败：脚本写死 `admin123` 登录，而 `render.yaml` 要求部署者填
强口令，两边必然对不上；`start.sh` 当时又是 `|| true` 吞掉错误，于是公网演示站长期
「服务正常、数据为空」且日志里没有任何线索。现已修复（口令随部署走 + 失败必留声），
回归用例见 `server/tests/test_prod_credential_guard.py::test_演示种子脚本的管理员口令随部署走`。
