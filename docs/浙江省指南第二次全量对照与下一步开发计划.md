## 〇、核对方法

不看上一版文档的结论，改为三步取证：

1. 从 `app.openapi()` 导出全部 488 个端点，按模块归并；
2. 从 `Base.metadata` 导出 153 张表的列清单；
3. 对每个指南条目，找出**具体承载它的表和端点**；找不到的才判为缺。

第 3 步是关键。"某模块存在"不等于"某条目已实现"——例如 `nursing_records`
表确实有护理记录，但它只挂在 `admission_id` 上，门急诊护理记录仍然无处可落，
所以 #3 依旧是 B。这类只看模块名就会判错的地方，下文逐条注明。

## 三、下一步开发计划（五个阶段）

排序原则：**先补口径，再补管控，最后补重构**。口径类差距的数据早就躺在库里，
只差算出来，投入产出比最高；权限模型重构影响面最大，放到有回归网兜底之后再动。

### 阶段一 医疗质量与费用口径补齐（#2 #14 #48 #49 #52 部分）

数据都已存在，本阶段基本是"把已有数据算出来"：

- **入出院诊断符合率**：`admissions.diagnosis_name` vs `case_summaries.discharge_diagnosis`。
- **治愈好转率 / 死亡率**：`case_summaries.outcome` 分布。
- **术前术后诊断符合率**：`surgery_records` 需补两列（术前诊断、术后诊断），一次迁移。
- **抢救成功率**：`emergency_cases` 需补转归列。
- **药占比**：住院取 `case_summaries.drug_cost / total_cost`；门诊按 `charge_items.category` 归集 `bill_details`。
- **抗菌药物使用强度**：`drug_rules` 需补 DDD 值与抗菌药标记，强度 = Σ(日剂量×天数/DDD)×100 ÷ 同期收治人天。
- **患者 360 视图纳入费用记录**（#2）。

产出：`/api/quality/clinical-indicators`、`/api/analytics/drug-use`，管理端一页承载。

### 阶段二 平台管控台（#46 #47 #55 价格 #27）

- **监控管理台**：运行环境概览（版本/启动时长/数据库连通/Redis 连通）、接口调用统计
  （复用访问日志）、定时任务与 ESB 节点状态汇总。
- **日志图形化**：审计量趋势、错误码分布、高频操作 TOP。
- **价格管理与公示**：`charge_items` 调价历史表 + 居民端价格公示接口。
- **就诊凭据**：发放/回收/作废，与电子健康卡号并存。

### 阶段三 门急诊文书补全（#3 #14 手术质量）

- 知情告知书（模板化、签署留痕、可关联手术/输血/特殊检查）；
- 门诊治疗处置记录；
- 门诊护理记录（把 `nursing_records` 的挂载从 `admission_id` 放宽到就诊/住院二选一）；
- 手术质量指标（非计划重返手术室、手术并发症率）。

### 阶段四 统一资源与申请单中心（#31 #32 #34 #53）

- 通用资源注册-发布-撤回模型，把号源/检查/手术间/血制品/工勤统一到一套资源表；
- 申请单排程与撮合（现有 `/api/service-requests` 从聚合视图升级为真正的排程中心）；
- 流程图形化编排（前端画布 → 生成既有 JSON 流程定义，后端不动）；
- DRGs 事前提示与事中预警。

### 阶段五 权限模型重构与安全加固（#43 #44 #78 #79 #81）

放最后，因为它要动所有路由的守卫：

- 角色表 + 权限点表 + 角色-权限关联，`require_roles` 改为查权限点；
- 六个内置角色作为预置数据保留，保证现有部署零感知升级；
- 审计防篡改（逐条哈希链）与归档；
- 错误信息脱敏统一出口；CSP 响应头。

**风险提示**：阶段五会触及 488 个端点的鉴权路径。现有 532 项测试是这次重构唯一的
安全网，动手前应先补齐"每个写接口的越权拒绝"用例，否则收不了口。

## 四、不建议做的事

- **#23 主题数据模型**：县域医共体的数据量（单县百万级人口）用不上数仓分层，
  现有按业务表直查配合已有的批量聚合优化足够。真要做，应该等接入省平台后
  按省侧口径建，而不是自造一套。
- **#34 图形化编排的后端重写**：JSON 流程定义已经跑通并有测试，图形化只应该是
  前端画布产出同一份 JSON，不要借机重做流程引擎。
