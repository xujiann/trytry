# 平台介绍 PPT（客户与投资方）

`县域医共体信息化平台介绍.pptx` —— 21 页，面向**客户**（卫健委、医共体牵头医院、招标评审）
与**投资方**的通用介绍材料。由 `build_deck.js` 生成，改内容改脚本、不要直接改 pptx，
否则下次重新生成就把手改的内容覆盖掉了。

```bash
npm install pptxgenjs          # 仅首次；仓库不带 node_modules
node docs/presentation/build_deck.js [输出路径]
```

## 页面结构

| 页 | 内容 | 面向 |
|---|---|---|
| 1 | 封面（平台定位 + 四个规模数字） | 全体 |
| 2 | 目录（六个部分） | 全体 |
| 3–4 | 政策依据与约束性目标、五个行业痛点 | 投资方为主 |
| 5–7 | 六层总体架构、五大类 36 项功能全景、平台规模 | 全体 |
| 8–11 | 四大核心场景：共享中心 / 药事协同 / 医防融合 / 运营监管 | 客户为主 |
| 12–13 | 全域慢专病子系统：十一端一体与八段业务闭环 | 全体 |
| 14–15 | 三端载体、技术架构 | 客户技术评审 |

每页都带**演讲备注**（`addNotes`），写的是这一页要讲什么、可能被问到什么，
放映时按需查看。

## 数字口径（重要）

脚本里出现的每个数字都有出处，**没有一个是拍脑袋写的**——客户和投资方现场追问时
应当能当场复核。改动平台代码后这些数字会漂移，重新出片前请按下表核一遍：

| 数字 | 出处 | 复核方法 |
|---|---|---|
| 946 个接口 / 730 条路径 / 90 个业务域 | `app.openapi()` | 见 `docs/系统功能清单.md` 文末的重新生成脚本 |
| 259 张表（慢专病 60 张） | `Base.metadata.tables` | 同上 |
| 89 个管理端页面 | `app/static/app.js` 的 `PAGES` 注册表 | 同上 |
| 2,360 项自动化测试 | `pytest tests/ --collect-only` | `cd server && python -m pytest tests/ -q --collect-only \| tail -1` |
| 89 个迁移 | `server/alembic/versions/` | `ls server/alembic/versions/*.py \| wc -l` |
| 六项 CI 阻断门、覆盖率门禁 70% | `.github/workflows/ci.yml` | 读 `COVERAGE_MIN` 与两个 job 的步骤 |
| 14 份 ADR | `docs/adr/` | `ls docs/adr/0*.md \| wc -l` |
| 36 项功能 / 379 项子功能 | `docs/功能指引对照表.md`、第七轮重审文档 | 逐条对照表 |
| 163 条慢专病需求 / 239 个子系统接口 | `docs/全域慢专病全流程管理系统_需求对照表.md` | 逐条对照表 |
| 政策文件与 2025 约束性目标 | 国卫办基层函〔2025〕121号等四份文件 | `县域医共体信息化平台建设规划.md` 第一章 |

## 措辞纪律

对外材料同样适用 `CLAUDE.md` 的诚实口径，已在片子里落实三处，**改稿时别把它们改成大话**：

- 第 17 页写明**等保测评、密评与异地灾备属部署期工作**，与"平台侧已完成"分开陈述
  （依据 `docs/信创适配与备份容灾.md` 的分栏写法）；同页写明 SM2/SM4 建议接硬件密码机，
  不宣称自实现国密。
- 第 11 页强调指标"同时给出分子、分母与口径，未采集的不进分母"，不报无法追问的数字。
- 全片**不含任何客户案例、上线数量、营收或市占率**——仓库里没有这些数据的出处，
  需要时由业务方补充并注明来源，不要在脚本里编。
