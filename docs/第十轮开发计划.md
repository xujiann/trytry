# 第十轮开发计划

第九轮把横向数据隔离读、写两个方向做完了。这一轮的主题是**收口**：
先补第九轮自己留下的半成品，再清两轮里登记在案的欠账，最后做一处
需要拍板的策略。

每条都附实测证据,不列"建议加强 XX"这类无法验收的条目。

---

## P0：AccessLog 只写不能查——第九轮建了一半

第九轮 P1 建了 `access_logs` 表，每次敏感调阅都记下"谁、什么时候、凭什么、
看了谁"，理由是《个人信息保护法》要求"谁查了谁的档案必须答得出来"。

**但它没有查询接口。** 实测：`grep AccessLog app/routers/*.py` 只有写、没有读。
一张答不出问题的合规日志，等于没建——真出了纠纷，数据在库里却调不出来。

对比：写审计 `audit_logs` 有 `/api/audit`、`/api/audit/export`、
`/api/audit/verify`、`/api/audit/stats` 四个读接口。读留痕一个都没有。

### 做法

- `GET /api/access-logs`：按患者 / 调阅人 / 机构 / 时间段 / 依据筛选，分页；
- `GET /api/access-logs/patient/{patient_id}`：**患者视角**——"哪些机构、谁，
  在什么时候看过我的档案"。这是《个保法》赋予患者的知情权，不只是给监管看的；
- 权限：管理员/院长看全量，患者本人（居民端 scope=portal）只能看自己被谁看过；
- 留痕表本身的调阅**也要留痕**——查"谁看了患者档案"这个动作同样敏感。

工作量小（一张表、两三个读接口），但它是第九轮承诺却没兑现的东西，排 P0。

## P1：实训报名超额——登记两轮的 check-then-act

第九轮 P2 登记、第八轮扫过同一类。实测确认仍在：

```
容量 2，6 人并发报名 → [201, 201, 201, 409, 409, 409]，实际报上 3 人
```

`enroll_plan` 里 `_enrolled_count(db) >= plan.capacity` 是 COUNT 式
check-then-act：并发下多人同时数到"还差一个"，一起挤进来。后果轻
（多几个学员），但它正是第八轮 D-6（疫苗超卖）同一个形状，
平台早有 `claim_quota` 原子占额的正确做法，只是这里没用上。

### 做法

给 `TrainingPlan` 加 `enrolled_count` 计数列 + 迁移，报名走 `claim_quota`
原子占额、退报名原子回退。附并发回归用例（改回旧写法要变红）。

顺带：`portal.add_family_member` 的 `MAX_FAMILY_MEMBERS` 也是同一形状
（居民加家庭成员），一并扫一遍——但它并发面窄，评估后再定改不改。

## P2：管理聚合统计的角色口径——第九轮 P6 挂起的策略

第九轮把 DRG 统计、基金统计、手术统计判为"聚合数、非明细"，没加机构墙——
这是对的（那是医共体管理本来要看的）。但它们**目前任意登录角色都能读**：
一个乡镇卫生院的经办，能拉到全县各机构的基金结余、DRG 例数均费。

这不是数据隔离漏洞（没有患者明细、不能写），是**角色策略**问题：
县域管理数据该给谁看。第九轮明确把它与数据隔离分开、挂起待定。

### 口径（已定：A 案）

管理聚合统计（DRG 统计、基金统计、手术统计等县域运行汇总）**限
director/admin**：乡镇经办、普通医生看不到全县各机构的财务/绩效汇总。

县域监测类（多点触发预警、迟报清单）**保持宽**——一线医生要看得到辖区
暴发信号,这条第九轮已定,不在本次收紧范围内。**分清这两类是关键**:
监测是"给一线的预警",管理聚合是"给管理者的账"——同样是跨机构聚合,
受众不同。

做法:给管理聚合接口加 director/admin 角色守卫。**先跑一遍现有用例**,
把以其他角色调用这些接口的测试找出来——要么是用例该改(测试用错角色),
要么是发现了一个不该限的接口(那就不是管理聚合)。第九轮反复验证:
每一次"收紧"都要由既有用例当场检验,不能改完拍脑袋说对了。

## P3：tests 存量 lint（housekeeping）

`ruff check tests` 现有 18 条告警：F841 未用变量×5、F541 无占位符 f-string×6、
F401 未用导入×3、E741 歧义变量名×3、M1×1。全是测试文件、与功能无关，
前几轮为避免把功能提交摊进十几个测试文件而一直没动。这轮单独一次清完，
`ruff check tests` 归零，之后纳入 CI。

---

## 不在本轮的（标准不变，理由照旧）

- **金额端到端 Decimal**：今为 `asdecimal=False`，Python 侧仍 float。
  留待接入真实医保结算同批做——没有真实结算场景，改了也验不出对错；
- **对接账号独立身份**：第九轮 FHIR 导出复用了 operator 角色并登记为遗留。
  真正对症是给对接账号单独一类身份并声明导出范围，属账号体系改造，
  等有真实区域平台对接需求再做；
- **SM2/SM4**：不自己实现密码算法；
- **DICOM 阅片 / 波形分析**：不做玩具版；
- **国产库适配**：没有环境实测，不写"已适配"。
