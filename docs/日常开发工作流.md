# 日常开发工作流（每日循环）

> 每天照此循环。核心纪律：**先计划、后编码**；**方向未审批不动手**；**merge 是人的决定**。
> 与治理体系配套：晨间读地图/路线，闭环每步都绑定本仓库既有的命令与守卫。

```
早上
  ├─ git pull                      # 拉最新，避免在旧基上开工
  ├─ CI 检查                       # 看昨夜/最近一次 CI 是否绿
  └─ 昨天 PR 检查                  # 昨天开的 PR：评审意见 / CI / 冲突 / 可否 merge

然后（定向阅读，先不写码）
  ├─ Read ROADMAP.md              # 今天该推哪块（Now 段）
  ├─ Read ARCHITECTURE.md         # → docs/CURRENT_ARCHITECTURE.md + 六张地图
  ├─ Read AGENTS.md → CLAUDE.md   # 硬规则、治理、童子军法则
  ├─ Read 相关 ADR                # docs/adr/：碰到的决策边界（尤其 0001/0002/0003）
  └─ Plan today's task            # 产出计划；**Do not code yet**

然后（开发闭环）
  PLAN  ─▶  审批方向  ─▶  实现  ─▶  tests  ─▶  /review  ─▶  PR  ─▶  merge
```

---

## 早上（开工前）

| 步 | 命令/动作 | 看什么 |
|---|---|---|
| `git pull` | `git pull origin <分支>` | 拉到最新，别在旧基上开工 |
| CI 检查 | 看 GitHub Actions 最近一次 `test` + `quality` job | 是否绿；红则先修/查，别叠新活 |
| 昨天 PR 检查 | 过一遍自己昨天开的 PR | 评审意见、CI 状态、有无 base 冲突、能否 merge |

> 若被订阅监听了 PR（`subscribe_pr_activity`），CI/评审事件会主动叫醒你——但仍以每日主动过一遍为准，webhook 可能漏。

## 定向阅读 + 计划（先不写码）

一次读这四类，够拼出"今天做什么、边界在哪"：

- **ROADMAP.md**：`Now` 段挑一项。别自己另起题目——路线没有的，先加进路线再说。
- **ARCHITECTURE.md**（→ `docs/CURRENT_ARCHITECTURE.md` + 六张地图）：确认要动的模块的依赖、分级（KEEP/IMPROVE/REFACTOR/REPLACE）。
- **AGENTS.md → CLAUDE.md**：硬规则第 1–15 条、治理棘轮、童子军法则（§12）。
- **相关 ADR**（`docs/adr/`）：要动的地方是否压着某条决策——碰核心数据/迁移/子域收敛，先看 0001/0002/0003。

**产出**：一份今日计划（要改什么、为什么、影响面、要不要 ADR、要不要特征化网）。**此时不写任何代码。**

## 开发闭环（七步，每步有门）

| 步 | 做什么 | 绑定的机制 / 命令 |
|---|---|---|
| **PLAN** | 写清方案：目标、涉及文件/表/接口、测试策略、是否需 ADR/特征化网 | 用 plan 模式产出，不落地 |
| **审批方向** | 把方案交人**审批方向**再动手；架构级的先落 ADR（`docs/adr/`，七段式） | 方向未批 → 不进下一步 |
| **实现（Codex）** | 按方案写码。动遗留代码前先补**特征化网**（`docs/特征化测试指引.md`）；顺手清理走童子军法则（§12，byte 安全、与功能分开提交） | 保持行为、限定范围（规则 1/15） |
| **tests** | `make verify`（build+lint+typecheck+test-unit）；动启动/核心链路加 `make test-smoke`；动迁移/PG 方言加 `make test-integration` | 新功能必带测试；不删测试凑绿（规则 9/11） |
| **/review** | 跑 `/code-review`（正确性 + 复用/简化）；碰认证/越权/加密/审计走 `/security-review` | 自查一遍再让人看 |
| **PR** | 准备就绪且**获授权**后开 PR；有模板按模板填；带上测试与影响说明 | 默认不擅自开 PR；开了可 `subscribe_pr_activity` 盯 CI/评审 |
| **merge** | **由人决定**。CI 绿 + 评审通过 + 无冲突才合 | Claude 不自动 merge |

**每天循环**：merge（或收工）后回到"早上"。

---

## 门与红线（别跳步）

1. **先计划后编码**：没有被审批的方向，不写实现代码。
2. **架构级先 ADR**：动子系统/依赖方向/认证/迁移机制/核心数据/破坏兼容 → 先 `docs/adr/`（触发冻结/不可变守卫变红，就是该写 ADR 的信号）。
3. **遗留代码先补网**：动没测试的遗留逻辑，先特征化网钉住现状，再改。
4. **绿了才往下**：`make verify` 不绿不开 PR；CI 不绿不 merge。
5. **PR / merge 是人的决定**：不擅自开 PR、不自动 merge。
6. **只进不退**：每次触碰让 lint/类型/契约/created_at 棘轮欠账变小，绝不变大（童子军法则 §12）。
