# 数据模型治理：输出 → 冻结 → 逐步迁移

按八步优化数据库结构。原则同接口治理：**不一次性重写**，锁基线、只进不退，用棘轮强制。
不改动现有表结构本身（那需迁移且属破坏性，正是第⑦⑧步要"逐步"而非现在做）。

| 步 | 目标 | 落地 | 状态 |
|---|---|---|---|
| ① | 输出现有 Schema | `scripts/dump_schema.py` → `docs/schema/SCHEMA.md`（246 表，可再生） | ✅ |
| ② | 分析表间关系 | `docs/DATA_MODEL.md` §2/§6（三套并行子域、76 spd 外键、共享底座三表） | ✅ |
| ③ | 找出实际使用 | 见下"使用分析"：**零死表** | ✅ |
| ④ | 建立 DATA_MODEL.md | `docs/DATA_MODEL.md` | ✅ |
| ⑤ | 建立 migration 体系 | alembic 双 head + 迁移纪律 + 零漂移守卫（`test_schema_governance.py`） | ✅ |
| ⑥ | 冻结核心表 | `FROZEN_CORE_COLUMNS` 快照棘轮 | ✅ |
| ⑦ | 新需求按新标准 | 下"新表标准" + created_at 硬约束棘轮 | ✅ 标准就位 |
| ⑧ | 旧结构逐步迁移 | created_at 欠账棘轮（只减不增）+ 迁移背包 | ✅ 机制就位 |

## ① 权威 Schema

数据库结构的**唯一真源**是 ORM 定义（`app/models.py` + `app/spd/models.py`）。
`server/scripts/dump_schema.py` 从元数据导出人可读快照 `docs/schema/SCHEMA.md`。
**改了模型就重跑该脚本**，文档不漂移。

## ②③ 关系与使用分析

- **关系**：详见 `docs/DATA_MODEL.md`。要点——246 表，主键统一自增整型；`patients`/`organizations`/`users`
  是共享底座（spd 76 个外键全指向这三张 + 其派生）；三套并行子域（慢病/专病/慢专病）。
- **使用**：把 246 张表映射到 ORM 类、grep 业务代码引用——**零死表**（每张表的类都在
  routers 等处被引用）。故本轮治理**不删表**，只做标准化与冻结。
- **已知非活跃**：`appointment_blacklist` 已在迁移中建后即删（合并进 `service_blacklists`），
  属正常演进，不在模型里。

## ⑤ migration 体系（纪律 + 守卫）

标准（照现状，勿破坏）：

1. **结构变更必须写 alembic 迁移**；`Base.metadata.create_all`（`main.py:113`）不算迁移，
   只在开发 SQLite 掩盖漏迁移，生产 PG 会缺表。
2. **升级用 `alembic upgrade heads`（复数）**——双 head（平台链 + spd 链）。
3. 每个迁移**必须实现 `downgrade()`**（当前 52/52）。
4. spd 迁移**自成分支**（`branch_labels=("spd",)`），不与平台链混挂。

守卫（`tests/test_schema_governance.py`）：
- `test_迁移恰有两个head_平台与spd`：锁双 head 纪律。
- `test_模型表零漂移_每张表都被迁移建过`：模型加表却漏写迁移 → 变红。

## ⑥ 冻结核心表

**核心表**（几乎所有业务与全部 spd 外键的落点，身份与主数据）：

`users` · `organizations` · `patients` · `encounters` · `admissions`

它们的**列集合**已快照进 `FROZEN_CORE_COLUMNS`（`test_schema_governance.py`）。任何增/删/改名
→ `test_核心表结构已冻结` 变红。这不是禁止演进，而是**逼着走 ADR**（`docs/adr/`）明确决策：

> 改核心表流程：① 写 ADR（背景/决策/影响）→ ② 写迁移 → ③ 同步更新 `FROZEN_CORE_COLUMNS` 快照 → ④ 绿。

## ⑦ 新需求按新标准（新表/新列必读）

新增表**必须**遵循（与现状约定一致，见 CLAUDE.md §4）：

- **主键**：`id` 自增整型。
- **审计字段**：**必须带 `created_at`**（棘轮强制，见⑧）；可变实体建议加 `updated_at`。
- **金额**：`Money`（`Numeric(14,2)`），禁 Float。
- **日期**：`String(10)` + `datetypes.DateStr`；时间戳 `DateTime` + `utcnow()`（naive UTC）。
- **状态**：裸字符串（不用 Enum），取值范围写列注释与路由 `pattern`。
- **外键**：能建就建 `ForeignKey("表.id")`；别用字符串软外键（spd 已有 30 处，勿再增）。
- **索引**：高频 `WHERE org_id/patient_id + status/date` 的表建**复合索引**（`Index("ix_…", …)`）。
- **命名**：与业务域一致；spd 表一律 `spd_` 前缀。
- **PII**：`id_card`/`phone` 沿用出口脱敏，勿绕过。

## ⑧ 旧结构逐步迁移（棘轮驱动）

历史欠账**只减不增**，一块一块补，不搞大改：

| 欠账 | 基线 | 棘轮 |
|---|---|---|
| 缺 `created_at` 的表 | **52 / 246** | `test_缺created_at的表不许变多`（新表漏 `created_at` 即红） |

迁移配方（每张老表）：
1. 写 alembic 迁移给该表加 `created_at`（`server_default` 回填历史行，见现有金额迁移范式）。
2. 模型加列、重跑 `scripts/dump_schema.py`。
3. 欠账降 1 → 把 `BASELINE_MISSING_CREATED_AT` 下调。

**下一批候选**（缺 `created_at` 且是持续增长的台账/流水表，优先）：
`admissions` · `vaccination_records` · `infectious_cases` · `voucher_entries` · `fund_settlements` ·
`qc_records` · `blood_stocks` · `visit_credentials` · `maternal_visits` · `child_visits` ·
`spd_measurements` · `spd_sync_logs`（完整清单见 `DATA_MODEL.md` §问题清单 P2-13）。

> `updated_at` 覆盖仅 10/246，暂不设硬棘轮（改动面大）；作为⑦"建议"项，新可变表自带即可。
