# 核心数据的不可变定义（Canonical Core Data）

> 核心概念**有且只有一个权威定义**。以后不应随便再造一套——这是本仓库头号技术债
> "三套并行子域"的止血闸。由 `tests/test_core_data_invariants.py` +
> `tests/test_schema_governance.py` 机器强制；变更需走 ADR（`docs/adr/`）。

## 为什么要这条

同一个概念在库里被造了三遍（见 `docs/DATA_MODEL.md` §2）：

| 概念 | 慢病 | 专病 | 慢专病 |
|---|---|---|---|
| 病种目录 | `chronic_disease_types` | `disease_programs` | `spd_programs` |
| 患者入组 | `chronic_patients` | `disease_enrollments` | `spd_enrollments` |
| 随访 | `followups` | — | `spd_followup_*` |

重复一旦落库就极难收敛：口径分叉、统计对不上、居民端出现两份互不相交的列表。
**不可变定义**就是不让这种事再发生在核心数据上——核心概念锁死为一个权威表，
新需求一律复用它、外键引它，而不是复制一份。

## 一、核心实体：一个概念 = 一个权威表

| 概念 | 权威表 | 身份 | 别处如何引用 |
|---|---|---|---|
| 患者主索引 | **`patients`** | `id_card` + `ehc_no`（全县唯一人物） | 外键 `patient_id`，**不得复制身份证号** |
| 机构主数据 | **`organizations`** | `org_type` + `parent_id`（县-乡-村层级） | 外键 `org_id` |
| 员工账号 | **`users`** | `username` / `password_hash` / `token_valid_from` | 外键 `user_id` / `operator_id` |
| 就诊记录 | **`encounters`** | `patient_id` + `encounter_type` | 外键 `encounter_id` |
| 住院记录 | **`admissions`** | `patient_id` + `admitted_at` | 外键 `admission_id` |
| 居民端账号 | **`resident_accounts`** | 手机号 / 微信 openid（`scope=portal`） | 外键 `account_id` |

这些表的**列集合已冻结**（`FROZEN_CORE_COLUMNS`，`test_schema_governance.py`），
**身份字段的归属已锁死**（`IDENTITY_OWNERS`，`test_core_data_invariants.py`）。

### 铁律

1. **人物身份存一处**：除 `patients` 外，任何表都不得引入 `id_card` / `ehc_no`；
   要表达"属于谁"，一律外键 `patient_id`。（既防第二患者主索引，也防 PII 明文扩散。）
2. **不另立平行主数据**：不得新建第二张机构层级表 / 第二套员工账号体系 / 第二个患者主索引。
3. **新概念先问"是不是已有权威表的延伸"**：慢专病要管的患者，仍是 `patients` 里的同一个人，
   只是多了纳管关系——用关系表（`spd_enrollments` 引 `patient_id`），不是再造一个人。

## 二、核心值类型：一种含义 = 一个类型定义

同样不可变，别自造：

| 值 | 权威定义 | 位置 |
|---|---|---|
| 金额 | `Money = Numeric(14,2, asdecimal=False)` | `app/models.py:44`（禁用 Float，`test_stage12_dialect` 守着） |
| 日期 | `DateStr` / `OptionalDateStr`（`String(10)` + 校验） | `app/datetypes.py` |
| 时间戳 | `utcnow()`（naive UTC） | `app/clock.py` |
| 脱敏 | `mask_id_card` / `mask_phone`（仅出口） | `app/privacy.py` |

新列涉及金额/日期/时间戳，直接用上面这些，不要临时 `Float`/`String` 自定义。

## 三、机器强制（守卫）

| 守卫 | 拦什么 |
|---|---|
| `test_core_data_invariants.py::test_身份字段只归属权威表` | 有人给别的表加 `id_card`/`org_type`/`password_hash` 等 = 另造核心身份 |
| `test_core_data_invariants.py::test_人物身份不得在别处另立` | 除 patients 外出现 `id_card`/`ehc_no` |
| `test_schema_governance.py::test_核心表结构已冻结` | 核心表增/删/改列 |
| `test_stage12_dialect.py` | 金额列必须定点数 |

## 四、要变更核心定义怎么办（ADR 流程）

不可变 ≠ 永不可改，而是**改动必须被看见**：

1. 写 **ADR**（`docs/adr/`）：背景、决策、被否决的方案、影响。
2. 写迁移（`downgrade()` 必须实现）。
3. 同步更新对应快照/白名单：`FROZEN_CORE_COLUMNS`、`IDENTITY_OWNERS`。
4. 重跑 `python scripts/dump_schema.py` 刷新 `docs/schema/SCHEMA.md`。
5. 绿。

> 一句话：核心数据的定义是**共享契约**，不是某个模块的私产——改它要开会（ADR），不能顺手。
