# 第十二轮：上线前完成度盘点与开发计划

问题：各模块功能完成度如何？上线前还差什么？下一步做什么？

方法：不采信既有盘点结论下判断（第九轮的教训——一张写着"覆盖率 100%"的表
照样漏了横向越权；第十一轮也是靠实测才敢下结论）。本轮**独立复测**功能覆盖，
再去查前十一轮**结构上看不见的东西**：它们一直在数功能条目，而上线卡的往往
不是功能。

日期：2026-08-24

---

## 一、结论先说

**功能不是瓶颈。** 独立复测四条，都没发现功能缺口：

| 复测项 | 做法 | 结果 |
|---|---|---|
| 需求追溯矩阵有没有虚报 | `docs/功能指引对照表.md` 引用的接口前缀 × OpenAPI 路径表 | 引用 **75** 个，查无此项 **0** 个 |
| 有没有"后端做了前端没接"的孤儿模块 | 86 个路由模块的**真实路由前缀** × 前端源码 | 只有 2 个零引用，且都合理（见 §2.2） |
| 页面是不是真能打开 | 浏览器登录后遍历全部页面 | 管理端 **89** 页 + 居民端 7 tab + 医师端 8 tab 全部渲染，**0** console 报错 / **0** 5xx |
| 代码里有没有烂尾 | 全量扫 TODO/FIXME/未实现 | 全仓 **10** 处；mock 全是**带接口的桩**（`MockGateway`/`MockWeChatProvider`），不是半截代码 |

**真正卡上线的是四件"没有真实环境就做不了、也验不了"的事**，外加平台侧自己
还能推进的治理欠账。下面分开说——这两类的排期逻辑完全不同。

## 二、复测细节（可复现）

### 2.1 规模基线（本轮实测）

- OpenAPI 路径 **730** 条 / 端点（方法×路径）**945** 个 / 路由模块 **86** 个
- 管理端 SPA 页面 **89** 个（登录后按角色过滤；未登录读到的 97 是未过滤值）
- 契约覆盖 **578/945 = 61.2%**，欠账 **367**
- 行覆盖率门禁 **70%**（CI 阻断），契约/lint/typecheck/集成 PG 六项全阻断

### 2.2 零前端引用的两个模块——都不是缺口

按文件名匹配会得出一堆假缺口（前端用的是 URL 前缀不是文件名）。改用每个
router 的**真实 prefix** 重算后只剩两个：

- `integration`（9 端点）：HL7 v2 / FHIR **入站**接口，供外部 HIS/LIS 调用，
  本来就不该有页面。有 56 处测试引用。
- `triage`（1 端点）：ADR-0006 拆倾倒场时新建，`/api/triage/suggest`。
  对照表里登记为已实现，有 5 处测试引用，但**管理端确实没有入口**。
  → 唯一一条"做了没接"的，工作量极小，列入线 B。

### 2.3 招标条目圈号 34/35 有落点，缺的那个是标注问题

代码里用 ①~㉟ 标注招标条目。全量抽取后 **⑰ 从未出现**。查证：⑰ 是
"结果互认目录化"，`/api/exams/recognition-items` + `/recognition-stats`
**已实现**，只是 Python docstring 里没打这个圈号。**是标注缺失，不是功能缺失**。

### 2.4 三套并行子域的真实体量（ADR-0003）

| 概念 | 路径数 |
|---|---|
| 慢专病 `spd` | 162 |
| 平台随访 `followups` | 8 |
| 专病 `disease_programs` | 8 |
| 慢病 `chronic` | 6 |
| 平台转诊 `referrals` | 2 |

spd 已是绝对主干。**读侧聚合只做完了转诊**一处；病种目录三份配置口径
（同一个 `hypertension` 码三处各带各的阈值）仍未合并。

## 三、上线阻断项（线 A）——都需要真实环境，平台侧验不了

这四条的共同点：**没有目标环境就没法验证，改了也不知道对错**。它们不是
"排期没排上"，而是必须在割接窗口前拿到环境才能做。

### A1 备份恢复目前**是路线，不是能力** ⛔ 最高优先级

`docs/运维手册.md` §4 自述得很清楚：

> 须在真实 PG 上跑通 `check`/`backup`/`restore_drill_pg.sh` 全链并实测归档
> 延迟后，RPO≤15min 才算达标——**在此之前本节只是路线，不是能力**。

脚本齐了（`backup.sh` / `restore.sh` / `restore_drill.sh` / `restore_drill_pg.sh`，
无 PG 环境自动转 dry-run），但**没有一次真实 PG 演练记录**。
指引"（四）完善数据信息安全保障"明文要求灾备中心——这条不过，不该上生产。

**做什么**：真 PG 上跑通全链 → 实测归档延迟 → 定点恢复（`--type=time`）验 PITR
→ 结果记台账。之后按季度演练、半年一次定点恢复。

### A2 四个外部通道全是桩

| 通道 | 当前默认 | 上线需要 |
|---|---|---|
| 支付 | `MockGateway`（下单即 paid，本地流水号） | 接真网关；注意真通道是**异步**语义，`payments.py` 已按异步写好 |
| 微信 | `wechat_provider="mock"` | 公众号 appid/secret + 网页授权回调 |
| 短信 | `sms_provider="console"` | 短信网关 + 签名报备 |
| 外呼 | `spd_call_provider="manual"` | 外呼平台对接 |

代码侧接口都留好了（`get_gateway()` / `get_wechat_provider()`），**风险在联调
不在开发**。`billing.py` 里已有一条硬防线：未配置/未过出网校验时**绝不静默
回落 Mock**（回落会把单标成已支付）。

### A3 PII 列加密默认关，开启有前置步骤

`pii_encryption_enabled=False`。`id_card`/`phone` 支持 SM4-CTR + HMAC 检索索引。
**开启前必须先跑 `scripts/pii_encrypt_backfill.py`**，否则存量明文与新密文混存。
等保/个保法语境下这是硬要求，流程见运维手册 §12。

### A4 信创适配（若合同要求）

从未在达梦/人大金仓/麒麟上跑过。`docs/信创适配与备份容灾.md` §2.1 有五步清单
和三个已知风险点（部分唯一索引 `uq_fund_pool_global`、`batch_alter_table`、
JSON 列映射），验收依据是**全量 pytest 跑通**，不是"点几个页面看着没问题"。
SM2/SM4 明确不自实现——接密码机，接入点是 `gmcrypto.py` 的 `mac()`/`hash_password()`。

> 该文档 §2.1 第 5 步写"确认 186 张表"，现已 258 张，**数字过期需更新**。

### A5 生产配置硬化核对

生产守卫已经很硬（弱密钥 / SQLite / 打种子数据在 prod 均**拒绝启动**）。
仍需人工确认这几项非默认值：`MEDPLAT_REDIS_URL`（缺则登出黑名单与防爆破失效，
仅告警不拒启）、`totp_required_roles`（空=双因子未强制）、`clamd_address`
（空=附件不杀毒）、`alert_webhook_url`（空=告警不外发）、
`audit_anchor_webhook_url`（空=审计链未锚定）、`session_idle_timeout_seconds`
（0=无空闲超时）。

## 五、本轮顺带修掉的一件事：字节捕获的噪声地板

治理文档原先写"同一份代码跑两次实测 2 处随机项，归一化后归零"。本轮重量：
**1879 个组合里 76 个有差异**。三类噪声漏在归一化表外——随机 `EHC…` 卡号、
**空格分隔**的墙钟串（原 `<TS>` 只认 ISO 的 `T` 形式）、随机实例 id。
补进 `capture_plugin.py` 后全局 **76 → 26**，spd 七个模块**全部归零**。

由此确立两条规矩（已写进 `docs/接口标准与治理.md`）：

1. **比对必须按模块划范围**——那 76 个全局差异没有一个落在被治理的模块内，
   只看全局会得出"改坏了"的错觉。
2. **噪声地板要按模块量、每批重量**，不能引用一次旧结论。

平台侧还剩 26 个噪声组合（`monitor` 累计计数、`esb` 令牌、id 排序等），
已在文档里点名登记——治理到那些模块前必须先归一化。

## 七、排期建议

```
割接前必须完成          ├── A1 备份恢复真 PG 演练      ← 最高优先级，且最容易被拖
（依赖真实环境）        ├── A2 四通道联调
                       ├── A3 PII 加密开启（先 backfill）
                       ├── A4 信创适配（若合同要求）
                       └── A5 生产配置核对

并行推进（平台自足）    ├── B1 契约收尾 367 → 0（一模块一提交）
                       ├── B2 统计口径合并
                       ├── B3 病种目录口径合并
                       └── B5 triage 入口

上线后                  └── C1~C5
```

**线 A 是关键路径，而且它不由开发进度决定，由环境到位时间决定。** 建议现在
就去要三样东西：一套真 PG（含归档）、四个外部通道的测试账号、（若要信创）
一套国产库环境。这三样不到位，线 B 做到 100% 也不能上生产。

## 八、这一轮做了什么、没做什么

- **做了**：独立复测功能覆盖（四条，见 §1），确认既有盘点结论成立；
  重量字节捕获噪声地板并修好工具（§5）；把上线缺口按"环境依赖 / 平台自足"
  分成两条不同排期逻辑的线。
- **没做**：没有验证 A1~A4 任何一条——它们**按定义就需要真实环境**，
  在这个容器里做不了，也不该假装做了。本文档给的是清单和失败信号，不是结论。
- **一处未逐条追溯的断言**（沿用第十一轮的如实标注）：驾驶舱"11 项指标卡对齐
  《监测指标体系（2024 版）》"，代码里显式追到指标号的只有 4/5/7/8/13。
  要逐条可验需要那份指标体系原文，手头没有，**既不宣称全对齐也不说缺了几条**。
