## 一、平台侧已完成（阶段十二）

### 1.1 金额列改定点数

46 个金额列（分布在 27 张表）从 `Float` 改为 `Numeric(14, 2)`。

**分两次做完，第一次漏了三个**：首轮按 `amount`/`price`/`cost`/`balance`/`total`/
`fee`/`budget`/`salary`/`pay` 这批命名族批量改，改了 43 列；但
`voucher_entries.debit`/`credit` 与 `payroll_records.perf_bonus` 不含这些词，
被漏在外面——**前两个正是整个复式记账、试算平衡表与合并报表求和的对象，
平台最核心的两个金额列反而漏在了第一遍**。教训：按命名批量处理之后必须回头
核对剩下的清单，不能只看匹配到的那一批。护栏的命名族已补上 `debit`/`credit`/
`bonus` 三个词，并配了"豁免清单里的列确实存在"的防腐用例。

**为什么现在做**：浮点存金额的误差在阶段七就露过头——`test_fund.py` 里不得不写
`abs(distributed_amount - 200000) < 1.0` 的容差断言才能通过。而国产库对浮点的
处理与 SQLite 又不相同，信创适配时这批列首当其冲，两件事分开做等于把 27 张表的
迁移做两遍。

**这一步买到了什么**：

- DDL 上是定点数，PostgreSQL 与国产库的 `SUM`/`AVG` 对 NUMERIC 是**精确**的；
- 14 位精度对县域金额量级（百亿以下、精确到分）绰绰有余；
- 换库时不会出现"同一笔账在两个库上算出两个数"。

**这一步没有买到什么**（重要，不含糊带过）：

`Money = Numeric(14, 2, asdecimal=False)` —— Python 侧仍收发 `float`，不是 `Decimal`。
打开 `asdecimal=True` 会让全平台上百处 `Decimal * float` 的算式直接 `TypeError`
（例如 `pool.total_amount * pool.prepay_ratio_pct / 100`），那需要连同每一处金额
计算一起改。所以：

- **库侧聚合是精确的**（PG/达梦的 SUM）；
- **Python 侧逐笔运算仍是浮点**，长链条累加仍有可忽略的末位误差。

端到端 Decimal 是一件独立的事，建议与接入真实医保结算同批做——那时每一处金额
计算都要复核，顺手改类型的边际成本最低。在那之前，`test_fund.py` 里的容差断言
保留，它诚实地记录着当前的精度边界。

### 1.2 可移植性护栏

`tests/test_stage12_dialect.py` 八条用例，测的**不是"能在达梦上跑"**——
没有那个环境就不该假装测过——而是"没有写下明显跑不到达梦上的东西"：

| 用例 | 盯的问题 |
|---|---|
| 手写 SQL 里没有库专有写法 | `AUTOINCREMENT`/`PRAGMA`/`GROUP_CONCAT`/`strftime`/`ILIKE` |
| 手写 SQL 总量可控（≤15 处） | 手写 SQL 越多换库工作量越大，数字涨了要有人解释 |
| 金额列一律定点数 | 防止新加的金额列又用回 `Float`；命名族含 `debit`/`credit`/`bonus` |
| 豁免清单里的列确实存在 | 防止豁免条目随表结构腐烂，变成绕过检查的后门 |
| 迁移脚本不写死 SQLite | 迁移里有库专有 DDL，换库第一步就过不去 |
| 金额列精度足够县域量级 | precision=14/scale=2/asdecimal=False |
| 部分唯一索引带方言参数 | D-2 的索引在 SQLite 与 PG 上语法不同，两边都要给 |
| 字符串列长度都有上限 | 无长度 `String` 在达梦上可能直接建不出来 |

扫描刻意**只查 `text(...)`/`execute(...)` 里的 SQL 字符串**，不扫全文件——
扫全文件会把 Python 的 `datetime.strftime` 和 `# pragma: no cover` 都误判成
库专有写法，那样的护栏很快会被人加豁免加到失效。

## 二、部署期必做（平台侧无法验证）

### 2.1 国产数据库适配清单

按顺序执行，每步都有明确的失败信号：

1. **装驱动**：达梦 `dmPython` + `sqlalchemy-dm`，人大金仓 `ksycopg2` +
   对应方言包。装不上就不用往下走。
2. **建库**：字符集 UTF-8，大小写敏感性与 PostgreSQL 对齐（达梦默认大小写
   不敏感，与平台的 `code`/`key` 唯一约束语义有出入，**必须显式设为敏感**）。
3. **跑全量迁移**：`alembic upgrade heads`。预计要盯的三处：
   - **部分唯一索引** `uq_fund_pool_global`（D-2）。若目标库不支持带 `WHERE`
     的唯一索引，改为**全域池写哨兵值 0 而非 NULL**——这条替代方案写在
     `models.FundPool` 的注释里，不是临场想的。
   - **`batch_alter_table`**：金额列迁移用的是批处理重建，在支持 `ALTER COLUMN`
     的库上 alembic 会自动走原生语句，不必改脚本。
   - **`JSON` 列**（`decision_points`/`answers`/`steps` 等）：达梦需映射为
     `CLOB` + JSON 约束，人大金仓支持 `jsonb`。
4. **跑全量测试**：把 `MEDPLAT_DATABASE_URL` 指向目标库跑 `pytest`。
   1000+ 条用例是这次适配唯一的验收依据，不要用"点几个页面看着没问题"代替。
5. **核对表与列**：用与 CI 相同的方法（从 `Base.metadata` 与
   `inspect(engine)` 双向 diff），确认 186 张表、列集合完全一致。

### 2.2 操作系统与运行时

- **麒麟/统信 + 鲲鹏/飞腾**：Python 3.11+；依赖清单见 `requirements.txt`，
  全部为纯 Python 或有 aarch64 轮子的包（FastAPI/SQLAlchemy/Pydantic/uvicorn），
  **平台没有引入任何需要本地编译的加密库**——国密走的是内置纯 Python SM3
  （见 `app/gmcrypto.py`），这一点正是为信创环境的可移植性留的。
- 前端是 build-free 的静态资源，无需 Node 运行时。

### 2.3 密码应用

`MEDPLAT_CRYPTO_SUITE=sm` 切换到国密套件（SM3 迭代口令散列 + HMAC-SM3 令牌签名）。

- 口令散列带算法前缀，**切换后老口令仍可登录**，不必强制全员改密；
- **SM2/SM4 平台侧不做实现**：纯 Python 的椭圆曲线既慢又难以保证抗侧信道，
  一个"能跑但不安全"的国密实现比没有国密更危险。需要 SM2 传输/签名的，
  应接国密硬件密码机或经检测认证的密码库，接入点是 `app/gmcrypto.py` 的
  `mac()`/`hash_password()` 两个函数。
- 传输层国密 TLS 由网关（如支持国密的 Nginx）承担，应用侧不参与。

## 三、备份容灾（阶段十三）

指引"（四）完善数据信息安全保障"明文要求灾备中心。平台侧能交付的是**可操作的
方案与脚本**，不是一句"由运维负责"。

### 3.1 备份对象与一致性

平台的状态分三处，**必须一起备、按同一时点备**：

| 对象 | 位置 | 不一起备的后果 |
|---|---|---|
| 数据库 | `MEDPLAT_DATABASE_URL` | —— |
| 附件文件 | `MEDPLAT_UPLOAD_DIR`（默认 `server/uploads/`） | 库里有附件记录、盘上没文件，报告点开是 404 |
| 平台密钥 | `MEDPLAT_SECRET` | 恢复后**全部令牌失效**（可接受），但**审计哈希链再也验不了**（不可接受） |

`scripts/backup.sh` 三者一起打包并写入清单，`scripts/restore.sh` 按清单还原。
**密钥不打进备份包**（打进去等于把锁和钥匙放一个盒子），而是校验环境变量里的
密钥指纹与备份时是否一致——不一致就明确告警，不静默恢复。

### 3.2 RPO / RTO 目标

县域医共体的业务特点是"白天忙、夜里闲"，故建议：

| 指标 | 目标 | 做法 |
|---|---|---|
| RPO（可容忍数据丢失） | ≤ 15 分钟 | PostgreSQL WAL 归档持续推送；SQLite 部署按 15 分钟增量快照 |
| RTO（可容忍中断时长） | ≤ 2 小时 | 灾备侧预置同版本应用镜像，恢复即启动 |
| 全量备份 | 每日一次（凌晨） | `scripts/backup.sh`，保留 30 天 |
| 恢复演练 | 每季度一次 | `scripts/restore_drill.sh`，**演练结果要留档** |

**恢复演练不做，备份等于没有**——这是这一节唯一真正重要的一句话。
备份脚本能不能跑，只有恢复的时候才知道，而那时候来不及了。

### 3.3 灾备中心

- 单数据中心内：网络设备与架构冗余（双上联、双电源），属机房建设范畴；
- 异地备份：按指引要求建异地备份中心或云化部署。平台无状态，
  应用侧只需保证同版本；有状态的是上面三样东西。

## 四、明确不做的事

- **不自己实现 SM2/SM4**（理由见 2.3）。
- **不做端到端 Decimal**（理由见 1.1），但把当前精度边界如实记在容差断言里。
- **不假装测过国产库**：`test_stage12_dialect.py` 测的是可移植性写法，
  不是兼容性结论。真正的验收要在目标环境按第二节清单跑一遍。
