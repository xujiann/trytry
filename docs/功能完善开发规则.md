> 给继续开发这个平台的人与 AI 代理。**CLAUDE.md 管"别弄坏"，本文管"怎样才算做完"。**
> 硬规则第 1–15 条、§8 安全红线、§11 接口标准、§12 童子军法则**原样有效**，本文不重复、不改写。

> 闸门：`tests/test_orphan_endpoints.py`（每条路径有入口或书面豁免）+ 既有五道棘轮。
> 立规日期 2026-09-15，基线 `8a728a3`；文中数字都是当天实测，**此后以生成的台账为准**。

## 0. 为什么需要这份规则

功能面已经铺满：《功能指引》36 主项 / 379 子功能全部有实现（`docs/功能指引对照表.md`、
`docs/第十一轮：功能落地盘点`），招标 163 条逐条有落点（`docs/全域慢专病…需求对照表.md`），
947 个端点、259 张表、91 个管理端页面。但"有"和"能用"之间还隔着一段，而且这段**从来没有定义过**：

| 口径 | 实测（2026-09-15） | 说明 |
|---|---:|---|
| `/api` 不同路径 | 730 | 87 个路由模块 |
| **没有任何前端调用形态的路径** | **209** | 三端脚本与页面逐字面匹配 |
| 其中按设计不需要界面 | 11 | HL7/FHIR 9、支付网关回调 1、设备批量回传 1 |
| **欠账：该有界面却没有** | **198（50 个模块）** | 见 `docs/模块完成度.md` 明细 |
| 无入口为 0 的模块 | 36 / 86 | 只有四成模块满足第一项完成定义 |
| 前端 `prompt(` 录入 | 134 处 | core 13 / clinical 61 / mgmt 32 / public 14 / spd 1 / doctor 9 / m 4 |
| 后端发了 `X-Total-Count`、前端读它 | 0 处 | 135 个分页端点的总数写完就扔（待裁定 P2-32） |

这不是新发现的一类问题，是同一类问题的第 N 次：2026-08-27 补 spd/care 时，22 条路径 / 31 个端点
**后端交付了、需求对照表逐条写着"已实现"、没有一个界面调用它们**，医生工作台还展示着一个
恒为 0 的"待回复咨询"计数。当时给 care 立了一条守卫，没有推广。本文把它推广成规则，
并把"做完"定义清楚——否则"完善各模块功能"没有终点，也没有起点。

**一句话：三张对照表里的"已实现"，含义是"有端点"。本文之后，"完成"只有一种含义，见 §1。**

## 1. 一个模块什么时候算「功能完整」（七项完成定义）

七项全满足才叫完整。前五项机检（`docs/模块完成度.md` 逐模块给数），后两项靠评审。
每项都允许**书面豁免**——豁免的形状写在最后一列，没写理由的豁免不算数。

| # | 要求 | 怎么检 | 书面豁免长什么样 |
|---|---|---|---|
| 1 | **每个端点有入口**：三端某处真的调用它 | `tests/test_orphan_endpoints.py`：路径逐字面匹配三端源码；欠账名单 `KNOWN_ORPHANS` 只减不增，接通一条划掉一条 | 对机器不对人（对接、回调、设备回传）→ `EXEMPT_PATHS` / `EXEMPT_MODULES`，一条一个理由 |
| 2 | **每个端点有契约**：`response_model` 与当前字节一一对应 | `tests/test_api_contract_governance.py`（已零基线，87 模块全治理） | 非 JSON 端点在 `responses` 里声明媒体类型（见 `docs/接口标准与治理.md`） |
| 3 | **列表能翻页，截断看得见**：列表走 `deps.paginate`；前端要么能翻页、要么至少显示"共 M 条" | `tests/test_list_pagination_ratchet.py`（后端半边）；前端半边等 P2-32 裁定后补闸门 | 嵌套子查询的业务上限（`NESTED_CAP_FALSE_POSITIVES`）；等机构/患者收口裁定的（`HELD_PENDING_SCOPE_DECISION`） |
| 4 | **归属校验与留痕**：写走 `assert_org_writable`/领域守卫，读患者资源走 `assert_patient_visible` + `AccessLog` | `tests/test_stage15_horizontal.py`（写侧两张零基线名单）、`test_unscopable_patient_reads.py` | 按设计跨机构（互认、转诊、全域角色）→ `BYID_CROSS_ORG_OK` / `DOMAIN_ORG_GUARDS`，带 ADR 或用例钉住前提 |
| 5 | **有测试**：主链路一条、越权反例一条（乙院对甲院应 403/404）、写唯一约束表的冲突一条 | 评审；CLAUDE.md §6 已是硬规则，本条只是把"测什么"说具体 | 无 |
| 6 | **有演示数据与手册条目**：`scripts/seed_demo.py` 能把这个模块灌出非空页面；`docs/用户手册.md` 或 `docs/培训手册/` 有它的一行 | 评审（手册标题与页面标题不一致，机检对不上，91 页里只有 34 页能按标题对上——所以这项**必须人看**） | 内部/机器接口无需手册；写在 PR 说明里 |
| 7 | **录入不靠 `prompt()`，状态文案取自后端** | `tests/test_frontend_prompt_guard.py` 盯含 `prompt(` 的行数，只减不增（存量登记 P2-38，现值见 `docs/闸门现状.md`）；`statusTag()` 与 `esc()` 由 `test_frontend_escape_guard` 守 | 无；存量按模块批次清 |

**怎样"宣告完成"**：不是在文档里写一句"已实现"，而是一次提交——让 `docs/模块完成度.md` 里这个模块那一行的
欠账列归零（或全部转成带理由的豁免），并在 ROADMAP 记一行。**没有让台账变化的完成，不算完成。**

## 2. 新功能怎么进来（开工前四问）

在写第一个端点之前，四个问题要有答案，写进 PLAN 或提交说明。

### 问一：需求来源编号是什么

合法来源只有这几类，写清编号：《功能指引》主项/子功能号、招标 163 条的端/条号、
《监测指标体系（2024 版）》指标号、`docs/待裁定事项清单.md` 的条目号（须已裁定）、
`docs/用户手册.md`/培训手册里写了却没有的操作、实测复现的缺陷（附复现步骤）。
**没有来源不开工**；路线上没有的，先加进 `ROADMAP.md` 再动（ROADMAP 首行的规矩）。

### 问二：落在哪一套，是不是改了名字其实已有

同一概念有三套并行实现（CLAUDE.md §5：病种目录 / 随访 / 转诊），ADR-0003 已定收敛方向。
碰这三个概念，先按 ADR-0003 判落点，**不建第四套、不把逻辑复制到另一套**。
同时对一遍 `docs/第七轮…子功能级重审` §三·3 的"换了名字，其实已有"清单——
资金管理 = `/api/fund`、移动办公 = `/m` 与 `/m/doctor`、汇总账簿 = `trial_balance`……
这张清单存在的目的就是让下一个人不必重新排查。

### 问三：是不是平台侧该建的

不是每条需求都该由本平台实现（见 §7）。设备与外部系统的职能（DICOM 阅片、波形分析、
车载定位、HIS 号源同步）平台只留接口，不做玩具版。判断标准：**实现主体是谁**。

### 问四：后端、界面、测试、种子、手册是不是同一批交付

一个功能的最小交付单元是**垂直切片**：端点 + 契约 + 界面调用 + 测试（§1 第 5 项那三条）+
`seed_demo.py` 一段 + 手册一行。可以分多次提交，但**同一批（同一个 PR 或同一个模块批次）交齐**。

后端先行只有一种合法形态：端点进 `EXEMPT_PATHS` 并写明"为什么这个端点不需要界面"。
没有理由、也没有界面的端点会被孤儿棘轮拦下——这是刻意的：care 那 31 个端点就是"后端先行、
界面下次"下次没来的结果。

## 3. 先做哪块（跨模块排序）

四级，级内再按两个次序：

1. **安全止血**（P0）：越权、留痕缺失、数据静默改写。任何时候插队。
2. **已交付功能的正确性缺陷**：口径算错、截断进统计、状态机漏路径。这些在页面上和"正常"长得一样，
   比缺功能更伤信任（第十五轮 48 条缺陷账本全是这一类）。
3. **完成度欠账**：按 `docs/模块完成度.md` 从上往下挑模块。级内次序——
   - **一线操作先于管理报表**：村医 / 医师 / 个案管理师每天点的入口，先于驾驶舱、统计、导出；
   - **写入口先于读入口**：能办事（认领、分配、提交、复核）先于能看到。
4. **新功能**：走 §2 四问。

**以模块为批次**：一次一个模块（或一个模块的一条业务链），一个提交，提交说明写"<模块>：<接通了哪几条> / 欠账 N → M"。
动遗留页面前先补 `scripts/fixtures/render_fixtures.json` 夹具、迁前迁后 `render_diff` 各比一次
（ADR-0009 十七批用过的手法，别省）。

**第一批建议**（按上面的次序从实测台账里挑，供裁定，不是决定）：
`spd/tasks`（9，任务分配/升级/提交/复核/批量——团队每天走的链路）→ `spd/population`（13，目标池认领/召回/服务申请，十一端的主干）
→ `portal` + `spd/portal`（18，居民端，含绑定手机/微信、我的知情同意、纠错、押金）→ `printing`（8，八种打印件模板都在，只差按钮）
→ `spd/config`（29，配置对象的改/删，多数与 `prompt()` 编辑器 P2-2 是同一件事）→ 其余 44 个模块。

## 4. 同一个文件，一套口径

往既有路由文件里加端点，**先读同文件的兄弟端点**，把它们的守卫、分页、契约、留痕原样照搬，再写业务。

这条规则的分量来自历史：本仓库同一个文件里两套口径的越权洞，一个月内确认了**八次**
（`upsert_medical_record` 有 `assert_org_writable` 而同文件的 `rescore_medical_record` 没有；
`enroll` 校验而同文件的 `record_node`/`exit_enrollment` 不校验；`claim_task` 的注释说"单条一直是校验的"而它恰恰没有……）。
洞不是没人知道要校验，是**写新端点的人没看旁边那个**。

具体做法：新端点的守卫写法与同文件出现次数最多的那种一致；不一致要在 docstring 里写为什么
（转诊天然跨机构、互认按设计跨机构——这类理由已有 ADR-0004/0005 可引）。
一句**永远不会触发**的守卫比没有守卫更糟（`update_program` 挂 `require_admin`，admin 属全域角色，
`assert_org_writable` 恒放行）——它让闸门不再问这个端点，问题原封不动。这种情况登记豁免并用用例钉住前提，不写假守卫。

## 5. 写下来的数字必须有东西盯着

文档里出现的任何数字，二选一：

- **有生成器 + 新鲜度用例**：`docs/schema/SCHEMA.md`、`docs/闸门现状.md`、`docs/模块完成度.md`、`docs/adr/README.md` 索引，都是这一对；
- **带日期 + commit**：如本文 §0 的表——读者知道它是哪一天的事实，过期了可以重测。

两者都没有的数字，在评审里按"未知"处理。这条来自一天之内的六次教训：`batch_tasks` 的注释、`clock.py` 的 docstring、
欠账清单的结论、ROADMAP 的"portal 余 48"、停在 0018 的 ADR 索引、以及 README/CLAUDE.md/系统功能清单里落后 68 个端点的规模数字。

## 6. 反模式（本月量出来的，别再犯）

- **判据比缺陷窄**：`async def` 不算端点、`db.query().first()` 不算取、docstring 被当代码、helper 只跟一层、
  只看 12 行就说"没有守卫"、只扫 post/put 看不见会写库的 GET。立判据先证明尺子量得准（`test_匹配器认得三种写法` 那种自证），再用它量。
- **计数代替名单**：一个总数会让"补一个、漏一个"净持平不红。欠账用显式名单，两个方向都钉（新增红、修好没划掉也红）。
- **零基线优于只减不增**：名单清空之后改成 `set()`，新出现一条就红，不需要有人记得去减。
- **"修好了"与"闸门看不见了"长得一样**：重构把取数推远一跳、把路由搬进子包、把文件改名，闸门都会静默变绿。
  每道闸门要带分母自证（`test_分母与语料都没有空转`）。
- **"已实现" = 有端点**：对照表只证明路由存在。完成看 §1。
- **恒为 0 的计数与 `prompt()` 录入**：一个永远是 0 的待办数、一个 `prompt()` 弹窗，都是"界面有了、功能没通"的记号，见到即登记。
- **后端先行、界面下次**：下次不会来。见 §2 问四。

## 7. 明确不做（集中一处，别再当缺口反复排查）

沿用 `docs/第七轮…子功能级重审` §三·2 与 §七、`docs/第十一轮：功能落地盘点` §四、`docs/通用平台能力补全开发计划.md` §三：

- **不自建阅片器、波形分析、车载定位**：DICOM 与波形归 PACS/心电设备，车载定位归车载终端；平台守住申请→报告→危急值→互认这条链。
- **不另做 HIS 同步器**：号源、库存同步走 `/api/esb` 总线。
- **不把国密写死**：算法适配层，默认通用算法，配置切换。
- **没有真实环境不写"已支持"**：达梦/人大金仓/麒麟、WAL 归档 RPO、四个外部通道（短信/微信/支付/电子证照）——环境到位当天用
  `scripts/channel_smoke.py` 与集成档跑出记录，再改文档。
- **不替客户拍板业务口径**：影响资金分配、考核分数、随访完成率分母的口径（ADR-0014 的 90 天 vs 30 天），
  写进 `docs/待裁定事项清单.md`，代码不动。
- **不做第四套**：病种目录 / 随访 / 转诊三套并行是历史债（ADR-0003），不是模板。

## 8. 台账与闸门（怎么知道做到哪了）

| 东西 | 位置 | 怎么用 |
|---|---|---|
| 逐模块完成度 + 无入口路径明细 | `docs/模块完成度.md` | 挑批次；做完一个模块该行归零。重跑：`cd server && python scripts/dump_module_completeness.py` |
| 孤儿端点闸门 | `tests/test_orphan_endpoints.py` | 接通一条从 `KNOWN_ORPHANS` 划掉一条；按设计无界面进 `EXEMPT_*` 写理由 |
| 各棘轮当前基线 | `docs/闸门现状.md` | 重跑：`python scripts/dump_gate_status.py` |
| 待人裁定的事 | `docs/待裁定事项清单.md` | 卡在口径的不自行决定 |
| 每日循环 | `docs/日常开发工作流.md` | PLAN → 审批方向 → 实现 → `make verify` → `/code-review` → PR → merge |

一个模块批次的提交里通常同时有：界面文件、`KNOWN_ORPHANS` 减少、`render_fixtures.json` 新夹具、
`docs/模块完成度.md` 重生成、（若加了端点）契约与测试、ROADMAP 一行。缺任何一样，`make verify` 或评审会拦。
