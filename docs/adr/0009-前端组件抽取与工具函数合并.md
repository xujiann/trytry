# ADR-0009：前端 render 组件抽取与三套工具函数合并

- 状态：**Accepted**（2026-08-21 批准）
- 日期：2026-08-20
- 决策者：待定（前端；影响三套前端的全部页面渲染）
- 相关：`docs/模块分级_KEEP_IMPROVE_REFACTOR_REPLACE.md`（第 155 行）、CLAUDE.md §8（`esc()` 转义红线）

## Problem（问题）

三套**免构建**原生 JS 前端，各写各的：

| 文件 | 行数 | `render*` 函数 |
|---|---|---|
| `app/static/pages-mgmt.js` | 1801 | 22 |
| `app/static/pages-clinical.js` | — | 31 |
| `app/static/core.js` | 1092 | 15 |
| `app/static/m/m.js` | 1139 | 19 |
| `app/static/pages-spd.js` / `pages-public.js` | — | 11 / 10 |

合计 **89 个 render 函数手抄同一个模板**：`panel` 外壳 + `table(...)` + 一段表单 + 一个 `msg` 元素。三套前端还各写了一遍 `$` / `esc` / `api`。

具体后果：

1. **转义靠人记**。`esc()` 是 CLAUDE.md §8 的红线，但 89 处手写插值里漏一处就是 XSS——本轮之前就修过 `pages-mgmt.js` 的 5 处 `<option>` 漏转义。抽成组件后，转义收在组件里，漏不掉。
2. **同一个修复要改三遍**。`esc` 的实现在三个文件里各一份，改一处漏两处。
3. **改样式要改 89 处**。

约束：**免构建是既定约束**（无 npm/bundler，`<script>` 直接引），这不是重写的理由——组件化不需要构建工具。

## Options（可选方案）

- **方案 A：维持现状**，靠 review 与静态扫描守 `esc()`。
- **方案 B：抽 `panel()` / `crudPage()` 等组件到一个共享文件**（如 `static/ui.js`），三套前端都引；`$` / `esc` / `api` 合并为一份。转义收进组件内部。
- **方案 C：引入前端框架**（Vue/React）重写。
- **方案 D：只合并 `$`/`esc`/`api` 三个工具函数**，render 不动。

## Advantages（各方案优点）

| 方案 | 优点 |
|---|---|
| A | 零成本 |
| B | 转义从"每处都要记得"变成"组件负责"；样式与交互改一处生效；新页面从抄 60 行变成填一个配置对象 |
| C | 生态成熟 |
| D | 成本极小（三份合一份），先消掉"改一处漏两处" |

## Disadvantages（各方案缺点）

| 方案 | 缺点 |
|---|---|
| A | XSS 靠人守；已经漏过一次 |
| B | 89 处逐个迁移，量大；组件抽象一旦定错，改回来更贵 |
| C | 违反免构建约束；三套前端全部重写，风险与工作量都不可接受 |
| D | 只解决三分之一的问题，89 处手写插值照旧 |

## Migration cost（迁移成本）

- 不动后端、不动接口。
- **方案 D 先行**：合并 `$`/`esc`/`api` 到 `static/ui.js`，三套引用它——约半天，风险极低（纯函数，行为一致）。
- **方案 B 主体**：先抽 `panel()` 与 `table()`（覆盖面最广的两个），再按页面逐个迁移。89 个 render 不必一次改完——组件与手写可以共存。估每页 20-40 分钟，总量 5-8 天，**可长期分批**。

## Risk（风险）

- **前端没有测试框架**（免构建、无 jest），改渲染只能靠人看 + 静态扫描。这是本方案最大的风险。缓解：
  - 本仓已有静态扫描范式（`test_portal_referral_frontend.py` 用正则/结构断言守 `esc()` 与接口调用），组件化后**扫描更好写**：只需断言"没有绕过组件的裸 `innerHTML` 插值"；
  - 迁移一页、人工过一页，不要批量改。
- 不做的风险：`esc()` 漏写的概率随页面数线性增长，而它的后果是 XSS。

## 落地记录：XSS 前提的实测复核（2026-08-22）

第一步（方案 D，`$`/`esc` 合并到 `shared.js`）已完成。着手第二步前，先把本 ADR
Problem 里最重的那条论据——"89 处手写插值里漏一处就是 XSS"——**实测了一遍**：

对三套前端全部 `.js` 做模板插值扫描，宽口径命中 **1892/2918** 处未见 `esc(`；
收窄到"文本类字段"（`*_name`/`title`/`remark`/`reason`/`summary`/…）仍有 **30** 处。
逐条核对这 30 处的结论是：**真实漏洞 0 条**。全部是——

- `alert()` / `confirm()` / `prompt()` / `setMsg()`（走 `textContent`，
  转义了反而把 `&` 显示成 `&amp;`）；
- 数字、SVG 坐标、颜色；
- 下游已经 `esc()` 的中间变量（如 `keys` 拼好后再 `esc(keys)`）；
- 前端自己定义的常量（`app.js` 的页面标题）。

只有两处是真的没转义，且都是服务端生成、格式固定的值（`lineChart` 的月份标签、
作业名进 `data-run` 属性），已顺手补上。

**这不改变结论，但要如实改一处措辞**：Problem 里"漏一处就是 XSS"描述的是**风险**，
不是**现状**——现状是转义纪律实际守住了。所以第二步的收益主要在**可维护性**
（改样式改 89 处、新页面抄 60 行），而不是"堵一个正在漏的洞"。据此，
第二步保持"长期分批、迁移一页人工过一页"的节奏是合适的，不需要抢工期。

反过来，扫描本身也验证了本 ADR 的核心论点：`barChart` 早就把 `esc(label)`
收在组件里了，它的全部调用点因此一处都不用操心转义。这是"转义收进组件就漏不掉"
目前**唯一已经成立**的样本，已用 `tests/test_frontend_chart_escaping.py` 钉住
（含防呆用例；三处变异验证）。

### 第二步启动：第一页已迁（2026-08-22）

`panel()` 抽出，放在 `core.js` 与 `table()` 并列——**不放 shared.js**：
`.panel`/`.card`/`table()` 是管理端这一套前端的标记约定，居民端与医师端（`m/`）
另有一套，塞进三端共用文件只会给那两端加一段永不调用的代码。

转义边界写死在组件文档注释里：**`title` 组件转义，`body` 不转**。`body` 是调用方
拼好的 HTML，组件替不了它——说清楚这条，免得"用了组件就安全了"变成错觉。

第一页迁的是 `renderServiceRequests`（两个面板 + 表格 + 表单，够典型又够短）。
用 Node 跑了一次**迁移前后渲染结果比对**：忽略标签间空白后，两版输出
逐字符相同——`panel()` 本身是纯粹的 no-op。

**而人工过这一页，找出了上面那轮全量扫描找不到的东西。**
那轮扫描的结论是"文本字段类命中 30 条、真实漏洞 0 条"，这个结论**有盲区**：
扫描只认 `x.y` 形式的属性访问，而这一页真正没转义的是一个**解构出来的局部变量**：

```js
const [text, color] = UNIFIED_STATUS[i.status] || [i.status, ""];
//                    查不到映射时 text 回落成后端原始状态码
<span class="tag ${color}">${text}</span>   // ← 裸插进 innerHTML
```

已修（`${esc(text)}`），比对脚本里用带载荷的未知状态码验证过：旧版把
`<img src=x onerror=alert(1)>` 原样吐进 HTML，新版转义。

所以要把上面那段"真实漏洞 0 条"的措辞再修一次：**准确的说法是"那套扫描口径下
0 条"**。逐页人工复核仍然会找到东西——这恰恰是 ADR 原文
"迁移一页、人工过一页，不要批量改" 的价值所在，不是走过场。

守卫见 `tests/test_frontend_panel_component.py`（8 条，含防呆；三处变异验证）。
**下一页照此办理**：迁完在函数里留 `ADR-0009` 路标，把该页加进那个文件的守卫。

### 第二批：又迁六页，并把"人工复核"升级成"按形状扫"（2026-08-26）

迁 `pages-mgmt.js` 的六页（随访 / 定时任务 / 满意度 / 站内消息 / 质量指标 /
运行监控），16 处手写外壳换成 `panel()`，输出逐字符一致。

**本批真正的产出不是那六页，是把上一批的个案修复补成了形状修复。**

上一批人眼撞见一处"解构出来的局部变量裸插值"，当时修掉就过去了。这次迁移前
先把**这个形状**在全仓库扫了一遍：

```js
const [text, color] = MAP[x.status] || [x.status, ""];   // 查不到 → text = 后端原始状态码
…
<span class="tag ${color}">${text}</span>                 // ← 裸插进 innerHTML
```

**还有 33 处**，散在 core.js(6) / pages-clinical.js(9) / pages-mgmt.js(5) /
pages-public.js(11) / m(2) 五个文件里。也就是说上一批的个案修复**漏掉了 97%**。

为什么既有的守卫没抓到：`tests/test_frontend_escape_guard.py` 原本盯的是
**行内**写法 `${MAP[x] || x}`——同一个缺陷换成"先解构、再插值"，插值处只剩一个
裸变量名，那条正则一条都匹配不到。已补上第二条守卫，并实测：在修复前的代码上
正报 33 处，修复后 0 处；`m/m.js` 那处兜底是字面量（`|| ["未分级", ""]`）
不误报。

**方法论上要改一句话。** 上面写过"逐页人工复核仍然会找到东西"，这条仍然成立，
但不完整——准确的说法是：**人工复核负责发现形状，发现之后必须立刻按形状全量扫，
不能只修撞见的那一处。** 上一批停在了前半句，代价是 33 处未转义又多活了四天。

配套工具：`scripts/render_diff.js`（+ `scripts/fixtures/render_fixtures.json`）。
在 Node 里按夹具把页面真渲染出来，拿迁移前后的 innerHTML 逐字符比。上一批那个
比对脚本是一次性的；按本 ADR"逐页迁、不设期限"的节奏，剩下约 300 处外壳还要迁
很久，每页重写一遍取证脚本不合算，故做成可复用的。夹具刻意塞 XSS 载荷——这样
比对的不是"标签没挪位"，而是"转义行为没变"。

一个迁移时才会暴露的坑：**标题里原有的 `esc()` 必须去掉**。`panel()` 自己转义
title，调用方再包一层就是转两遍（`&` → `&amp;amp;`），页面上直接显示出转义序列。
`renderMonitor` 上实测到 `本实例进程内&lt;b&gt;` → `本实例进程内&amp;lt;b&amp;gt;`，
已加守卫 `test_已迁移的页面标题不得重复转义`。

**自审又补了一课：守卫的判据必须与缺陷同宽。** 上面三条守卫写完跑绿之后，
用合成用例逐条试穿，三条**全都能绕过**：判据限定了"映射名首字母大写"
（而本仓库的 `spdTag(map, key)` 就是小写形参）、"兜底数组第二个元素恰好是 `""`"
（带个默认配色就绕过）、"`panel(` 后紧跟反引号"（标题是单个动态值时最自然的
写法没有反引号）。这些差异**与缺陷本身毫无关系**，纯粹是拼写。

判据比缺陷窄，等于给缺陷留了个拼写上的后门，而且是**看不见的**后门——
守卫是绿的。这与本节开头那条教训是同一件事的两面：修复要按形状，判据也要按形状。
三条现已放宽到与缺陷同宽，并各补了参数化的"绕过尝试"用例把这些写法钉死；
放宽前后在修复前的代码上都正报 33 处，没有靠放宽把账做小。

**取证工具本身也要被验一遍。** `render_diff.js` 自审出五处"看着绿其实没验到"，
最要紧的是空表假绿：夹具"列表必须非空"这条约定只写在注释里没有真检，而空列表下
`table()` 照样吐一整个"暂无数据"的表格、长度好几百，于是报"逐字符相同"——
**行模板一次都没求值**，而那里恰恰是 `esc()` 的唯一出现处。
一个用来出具"字节没变"证明的工具，自己的证明力有洞，比没有工具更危险。

同一次形状扫描还带出**第三种失败方式**——查表根本不写兜底
（`const [t, col] = SS[s.status]`）。这个的后果比未转义更直接：解构 undefined
抛 TypeError，而它在 `table()` 的行渲染回调里，于是**整页白屏**。全仓库只有一处，
但是个真的：`renderMedication` 的缺药登记，`SS` 只有三个流转态，后端却会写
`collected`/`no_show`/`cancelled`——只要有一条登记结了案，这一页就打不开。
已修并加守卫。三种写法（兜底未转义的行内式 / 解构式 / 干脆没有兜底）现在都有守卫。

**全量插值扫描刻意没有做成门禁**：30 条命中 0 条真阳性，做成棘轮只会天天误报，
最后被加豁免加到失效。门禁收在信噪比真正好的地方——共用的图表组件。

### 第三步：`statusTag()` —— 本 ADR 的论点第一次真的兑现（2026-08-26）

前面两批都是"迁面板"，收益是可维护性。这一批不同：**它把上一批那 33 处未转义
从"修好了"变成"写不出来了"。**

那 33 处全是在手抄同一段三行代码：

```js
const [text, color] = MAP[x.status] || [x.status, ""];
`<span class="tag ${color}">${text}</span>`      // ← esc() 谁都可以忘，而且都忘了
```

而同一个仓库里 `spdTag()` 早就写对了（`map[key] || [...]` + `esc(text)`）——
**只是没铺满**。这正是 CLAUDE.md §6 说的"横切能力多半已抽好，只是没铺满，
优先复用而非新建"。抽成 `statusTag(map, key)` 之后，34 个调用点连"要不要转义"
这个问题都不会遇到。`barChart` 是本 ADR 论点的第一个样本，这是第二个——
而且是**有血的**那个：第一个样本从来没出过事，这个出了 33 次。

三条判断值得记：

1. **放 `shared.js` 而不是 `core.js`。** `panel()` 当初放 core.js 的理由是
   `.panel`/`.card` 是管理端独有的标记约定。这次判据不变、结论相反：`.tag`
   **三套前端都在用**，且标记契约逐字相同（`style.css:60` 与 `m/m.css:141`
   各自定义 `.tag` 与 `.tag.red/.green/.orange`，配色不同、类名约定一致）。
   判据始终是"三端是不是真的都在用"，不是"看起来像不像工具"。

2. **合并实现 ≠ 统一行为。** 慢专病历来把空状态显示成 `—`、管理端显示空白。
   合并时**没有**顺手统一——那是改字节不是去重。两套约定各自留在调用点上
   （`spdTag` 委托时自己传 `key || "—"`），共用的只是实现。

3. **等价性是证出来的，不是推出来的。** 34 个调用点散在 6 个文件里，逐页造夹具
   不现实，于是换一种取证：`scripts/statustag_equiv.js` 把**表达式本身**在一个
   输入矩阵上跑一遍逐字符比（命中/未命中/空串/null/undefined/XSS 载荷/数字状态码）。
   表达式等价 + 替换是纯文本替换 ⇒ 每个调用点都等价。
   **矩阵当场抓到一条真问题**：初版组件用 `key || ""` 兜底，会把慢病分级的 `0`
   吞成空白（本仓库确实有数字状态码），改用 `key ?? ""`。
   慢专病侧的委托另有一条**前提**（传进来的映射表不能用假值当键），脚本里真的
   扫了 5 张表去验，没有默认它成立。

一条如实记下的**覆盖缺口**：居民端/医生端的 4 处只有等价性证明与人工复核，
**没有字节比对**——`render_diff.js` 只加载管理端那套文件。要补就得给它加第二套
入口，属另一件事。

机械替换这件事本身也有个教训：脚本按"变量在块内只被用了一次"来判断能不能安全
替换，结果把 CSS 的 `color:#b23c3c` 也数成了一次"用途"，于是跳过了两处。
**跳过是对的**——`pages-public.js` 那处 `color` 真的被第二个 span 复用了，
机械替换会把它替坏。宁可少替、留给人看，也不要替错。

### 第三批：夹具已有的五页（2026-09-02）

物资 / 用药 / 计费结算 / ESB / 慢专病中心端，22 处手写外壳换成 `panel()`，
`render_diff` 五页逐字符一致。挑页的依据不是业务重要性而是**取证成本**：比对器
13 个页面键里还剩这五页带手写外壳，夹具现成，不用先造数据。

两条记下来：

1. **模板骨架不要动。** 把 `innerHTML = \`\n    <div class="panel">…\`` 改写成
   `innerHTML = panel(…) + panel(…)`，肉眼看是等价的——比对器报了三页差异，
   差在第 14 个字符：模板字面量开头那个换行+缩进是一个**文本节点**，`+` 拼接
   把它丢了。改回 `\`\n    ${panel(…)}\n    ${panel(…)}\`` 后一致。"忽略标签间空白"
   不覆盖首个标签之前的空白，这是对的：它确实是 DOM 里的一个节点。
2. **第一次迁出 `pages-mgmt.js`。** 守卫 `test_frontend_panel_component.py` 此前
   只读 mgmt 那一份源码，现改成按函数名在全部 `static/*.js` 里找定义
   （恰在一个文件里，否则报名字）。`panel()` 仍留在 core.js：三个页面文件都在
   core.js 之后加载（`index.html` 的 script 顺序），不需要挪。

剩余手写外壳 277 处（core 44 / clinical 97 / mgmt 52 / public 36 / spd 48）。
往后每批的主要成本是给页面补夹具：非空数据 + XSS 载荷，缺一样比对就是假绿。

### 第四批：先补夹具再迁的五页（2026-09-02）

团队端 / 卫健委端 / 公文排班质控 / 传染病 / 血库，24 处外壳。夹具成本第一次真正付出：

1. **条件面板的条件要推成真。** 团队端的预警与服务包、血库按角色显示的两个表单、
   传染病的预警，都是 `cond ? <panel> : ""`。夹具若让条件为假，那段模板根本不求值，
   比对只是在比一个空串——与 `_readme` 说的"空列表钉不住字段"是同一个坑。
   role 类条件走夹具的 `localStorage` 键（`spd_team_role` / `medplat_role`）。
2. **迁移前先比对一次。** 夹具刚写完、页面还没动时跑 `render_diff`，看的不是"是否相同"
   （必然相同）而是**字符数**：1061～5026，证明表格与面板真渲染出来了。夹具写错字段名
   时页面会走"—"/"暂无数据"分支，字符数一眼就小得不对。
3. **没有标题的外壳不迁。** `renderEldercare` 有一处 `<div class="panel">${table(…)}</div>`，
   `panel()` 必带 `<h3>`，迁了就是改字节。也不该为它给组件加"无标题"分支——
   那是让组件迁就一处例外。这类外壳留着，页面就不进 `MIGRATED_PAGES`。

剩余手写外壳 253 处（core 44 / clinical 90 / mgmt 52 / public 32 / spd 35）。

### 第五批：接种 / 医案 / DRGs / 科室成本（2026-09-02）

四页 17 处。夹具里的三个判断：

1. **不调接口的页，夹具 `api` 就该为空。** 接种页四个面板全是表单 + 空结果容器
   （查询结果由提交后的回调再渲染），渲染时一个接口都不调。硬塞一份假数据反而
   是在骗自己"钉住了数据行"；这页比对钉的是外壳与表单字节，如实写进 `_why`。
2. **共前缀的接口靠最长前缀分流。** `master-cases` 与 `master-cases/stats`，
   比对器按 `url.startsWith(key)` 取最长的 key，带查询串的 `master-cases?include_draft=true`
   只匹配短 key。写夹具时要意识到这条规则，别把两个接口写成一个键。
3. **标题里的动态值不再 esc()。** 成本页 `<h3>${esc(period)} 科室成本</h3>` 改成
   `panel(\`${period} 科室成本\`, …)`——组件转义标题，留着 esc 就是第二批那个
   `&amp;amp;` 问题；守卫"标题不得含 esc()"正是为这一步立的。

剩余手写外壳 236 处（core 44 / clinical 82 / mgmt 47 / public 28 / spd 35）。

### 第六批：运行中枢 / 监测 / 通用资源 / 医保（2026-09-02）

四页 17 处。两条：

1. **渲染函数在 innerHTML 之后还有活，夹具要把它喂饱。** 运行中枢页赋完 innerHTML
   还会 `await spdMeta()` 建两个规则编辑器；夹具没给 `/api/spd/meta` 时函数直接抛错，
   比对器报的是"渲染失败"。这不是比对器的缺陷——真浏览器里同样会白屏——但要分清
   "夹具没喂饱"与"迁移改坏了"，先看错误再看差异。
2. **比对钉的是不变，不是安全。** 医保页特病申报的状态字面量是裸插的后端枚举，夹具照给
   载荷，迁移前后输出一致即通过。"这里该不该 esc" 是另一条线的事
   （`test_frontend_escape_guard.py`），迁移这一步不顺手改行为——改了就不是 no-op，
   比对器会红，而且那样一个提交里就混了两件事。

### 第七批：知识库 / 人力财务物资 / 医疗质量 / 慢专病考核 / 慢专病随访（2026-09-06）

28 处手写外壳换成 `panel()`，第一次一次迁五页、跨三个文件。节奏同前：五页各造
`render_fixtures.json` 条目，迁前比一次（2486～7057 字符，证明表格与条件面板真渲染出来了），
迁完再比一次仍逐字符相同，最后把**全部 31 个夹具页**一并重跑，无一差异。

这一批新学到的三条：

1. **计数规则看不见带附加 class 的外壳。** 守卫数的是 `<div class="panel"`（`panel` 后紧跟
   引号），而 `renderHrFinance` 里那两个"先渲染成 hidden、点击后填内容"的容器写的是
   `class="panel hidden" id=…`——规则一直数不到它们。它们也确实迁不了：`panel()` 固定输出
   `<div class="panel"[ style=…]>`，出不了额外 class 与 id，迁了就是改字节。结论写进守卫注释：
   别把"计数为 0"读成"这页一处手写外壳都没有了"。
2. **比对器只覆盖渲染路径，点击之后的 HTML 证明不了。** `renderSpdAssess` 的第 6 处外壳在
   "下钻明细"的点击回调里。它的标题现在是 `${esc(d.object_name)} · …`，换成 `panel()` 要把
   `esc` 去掉交给组件——**通常**等价，但若后端把 `total_score` 这类数值字段返回成带 `&` 的
   字符串，两种写法的字节就不同了。没有证据就不换：留着，登记进 `KNOWN_UNMIGRATED_SHELLS`
   并写明"等取证工具能覆盖点击路径再说"。
3. **顺手补登两页**：`renderSpdMember` / `renderSpdManager` 本来就是 `panel()` 写的，却从没
   进过白名单——没登记就等于没有"不许退回去"的网。

### 第八批：住院文书 / 手术麻醉 / 流程引擎 / 运营分析（2026-09-06）

20 处外壳换成 `panel()`，全部落在 `pages-mgmt.js`——这个文件此前只迁过零星几页，是剩余量最大的一份。
节奏同前，五页各造夹具、迁前迁后各比一次，最后 **36 个夹具页**全量重跑无一差异。

**这一批最有价值的产出不是迁移，是备夹具时发现的一个真缺陷。**
`renderAccounting` 的合并报表面板整段落在凭证 `table()` 的**行回调**返回值里——每条凭证都会
重复输出一整份合并报表，而且嵌在 `<tr>` 内（浏览器会把它甩出表格）。用夹具实测：两条凭证 →
"合并报表"在页面上出现 **2 次**；生产上 30 条凭证就是 30 份。成因是模板字符串的反引号收错了
位置，不是逻辑写错。

处理方式是**不顺手修**：修它会改字节，而迁移这一步的全部价值就在于"输出一个字节都没变"。
于是这一页整页留下不迁，缺陷登记进 TECH_DEBT P1-41，夹具 `accounting` 先留着——修的时候
正好拿它做修前修后的对比。这条也补上了一个方法论结论：**为了迁移而造的夹具，本身就是
读页面的一种方式**，比通读模板字符串更容易看出结构性错误。

剩余手写外壳 172 处（core 44 / clinical 56 / mgmt 27 / public 25 / spd 20）。

## Recommendation（建议）

**分两步，先做 D 再做 B**：

1. **立即可做**：合并 `$` / `esc` / `api` 为一份（方案 D）。半天、低风险、消掉"改一处漏两处"。
2. **随后长期推进**：抽 `panel()` / `table()` 并逐页迁移（方案 B），**每次只迁一页**，不设完成期限。

**否决方案 C**：违反免构建约束，且重写三套前端的风险与收益完全不成比例。

落地第一步：把 `esc()` 的三份实现合成一份并加一条守卫用例（三套前端都不得再自定义 `esc`）——这一步本身就消除了一类 XSS 风险来源。需要前端批准。
