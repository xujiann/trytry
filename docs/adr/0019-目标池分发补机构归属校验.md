# ADR-0019：慢专病目标池分发补机构归属校验

- 状态：**Proposed**（待人工复核 —— CLAUDE.md §8「涉及越权的改动走 ADR 并请人复核」）
- 日期：2026-09-06
- 决策者：待定（需业务侧确认「谁有权跨机构分发目标人群」）
- 相关：CLAUDE.md §8（越权红线）、`app/visibility.py`、`tests/test_stage15_horizontal.py`
  （按 id 写接口的机构归属棘轮）、TECH_DEBT **P2-12**（本问题最初被记成「未用参数」）

## Problem（问题）

`POST /api/spd/candidates/distribute`（`app/spd/routers/population.py:750`）
**按 id 直取目标池记录、不校验归属**：

```python
rows = db.query(SpdCandidate).filter(SpdCandidate.id.in_(body.candidate_ids)).all()
for candidate in rows:
    if body.org_id is not None:
        candidate.org_id = body.org_id      # ← 可以把别家的记录改挂到自己名下
    ...
```

函数签名里有 `user: User = Depends(get_current_user)`，但**函数体一次都没用它**。
TECH_DEBT 里这条被记成 P2-12「未用参数」，括号里带了一句"后者导致缺机构校验"——
它其实不是清理项，是**横向越权**。

同一个路由文件里的兄弟接口 `claim_candidate`（`:770`）就是对的：

```python
candidate = db.get(SpdCandidate, candidate_id)
assert_org_writable(db, user, candidate.org_id)     # ← 分发接口缺的正是这一行
```

角色面：`SERVICE_ROLES = ("doctor", "public_health", "director")`，而
`GLOBAL_ROLES = {"admin", "director"}`。也就是说 `director` 本来就是全域角色、跨机构分发
对它是合法的；**漏掉校验放开的是 `doctor` 与 `public_health` 这两个本该只能写本机构的角色**。

**已实测复现**（临时探针，非留仓用例）：建甲、乙两院与一个挂甲院的 `doctor` 账号，
往乙院落一条目标池记录，再用甲院 doctor 调分发接口：

```
乙院目标池记录 id = 1  org_id = 2
甲院 doctor 分发乙院记录 -> 200 {"distributed":1,"not_found":0}
改后 org_id = 1  status = target  assigned_user_id = 1
```

一次请求把别家的目标人群**改挂到自己机构、改了状态、指派给了自己**，返回 200。
`candidate_ids` 上限 500，可批量。

危害不止"看见别家"：目标池是慢专病纳管的入口，被改挂之后
后续签约建档、任务派发、考核计数都会跟着挪到错误的机构。

## Options（可选方案）

- **方案 A：维持现状**，在 TECH_DEBT 里记一笔。
- **方案 B：逐条校验来源 + 校验去向**——对每条记录做 `assert_org_writable(db, user, candidate.org_id)`，
  并对 `body.org_id`（要改挂到的目标机构）同样做一次；任一条不合规整个请求 403。
- **方案 C：静默跳过越权的那几条**，在响应里多一个 `forbidden` 计数（比照现有的 `not_found`）。
- **方案 D：查询阶段就按可见机构过滤**（`visible_org_ids`），越权的记录直接落进 `not_found`。

## Advantages（各方案优点）

| 方案 | 优点 |
|---|---|
| A | 零改动、零风险 |
| B | 与同文件的 `claim_candidate` 完全同款；语义最直白（越权就拒），批量操作不会半成功 |
| C | 合法的那部分照做，调用方不必自己筛 id |
| D | 天然幂等，不新增错误码；越权与不存在在响应上无从区分（对攻击者也不泄露存在性） |

## Disadvantages（各方案缺点）

| 方案 | 缺点 |
|---|---|
| A | 越权继续可用；且这条已在 TECH_DEBT 里躺着被误标成 P2 清理项 |
| B | 前端若一次勾选跨机构的记录会整批失败——但那本来就是不该发生的操作 |
| C | **半成功**：返回 200 而实际只改了一部分，调用方多半不看那个计数；与批量语义相冲 |
| D | 把"越权"伪装成"不存在"，出问题时排查困难；且与 `claim_candidate` 的 403 不一致 |

## Migration cost（迁移成本）

极小：两行校验 + 一条回归用例。不动表结构、不动响应模型（合法路径的响应字节不变）。
`director` / `admin` 走 `GLOBAL_ROLES` 直接放行，现有的中心端跨机构分发**不受影响**。

需要一并确认的是：`tests/test_stage15_horizontal.py` 的「按 id 写接口机构归属」棘轮
**没有把这个端点算进欠账**——补校验的同时要弄清它为什么漏掉，否则同形状的还会有第二个。

## Risk（风险）

- **行为变化**：今天 200 的越权调用会变成 403。若线上真有基层账号在跨机构分发（属于误用），
  会当场报错——这正是要的效果，但需要业务侧知情。
- **漏改同形状的兄弟接口**：本 ADR 只盯这一个端点。落地时应按形状扫一遍
  `app/spd/routers/` 里"按 id 批量改、且签名里有 user 却没用"的写接口。
- 不做的风险：横向越权持续可用，且被记成 P2 之后**优先级被系统性低估**。

## Recommendation（建议）

**取方案 B**，理由是它与同文件既有的正确实现逐字同款——越权修复最不该做的事就是
在同一个文件里发明第二套语义。`director`/`admin` 不受影响，改的只是本就不该放开的两个角色。

落地清单：
1. 逐条 `assert_org_writable(db, user, candidate.org_id)`；对 `body.org_id` 也校验一次
   （改挂进一家自己都写不了的机构，同样是越权）。
2. 补回归用例：甲院 doctor 分发乙院记录必须 403，且记录一个字段都不许变；
   同院分发仍 200；`director` 跨机构仍 200。
3. 查清 `test_stage15_horizontal.py` 为什么没把它算进欠账，并按形状扫
   `app/spd/routers/` 有没有同款遗漏。
4. TECH_DEBT 里 P2-12 拆出这一条，按越权登记（P1）。
