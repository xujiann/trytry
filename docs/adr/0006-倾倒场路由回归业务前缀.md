# ADR-0006：倾倒场路由（gapfill / service_extras）回归业务前缀

- 状态：**Accepted**（2026-08-21 批准）
- 日期：2026-08-20
- 决策者：待定（后端 + 前端；影响 54 个端点的文件归属，不影响 URL）
- 相关：`docs/模块分级_KEEP_IMPROVE_REFACTOR_REPLACE.md`（C 类，第 107-108 行）、`docs/特征化测试指引.md`、`docs/API_MAP.md`

## Problem（问题）

两个文件按**验收条目号**而不是业务域分区，成了倾倒场：

| 文件 | 行数 | 端点 | 塞了几个业务 |
|---|---|---|---|
| `app/routers/gapfill.py` | 1125 | 34 | 6 个前缀：`/api/tcm`、`/api/cssd`、`/api/education`、`/api/maternal`、`/api/homevisits`、`/api/performance` |
| `app/routers/service_extras.py` | 521 | 20 | 裸 `/api` 前缀，7 个互不相干的业务 |

后果是具体的，不是洁癖：

1. **前缀重叠**：`gapfill.py` 里有 `/api/performance`，`routers/performance.py` 里也有 —— 同一个 URL 前缀的实现分在两个文件，改一处漏一处。`/api/tcm` 与 `routers/tcm.py`、`/api/education` 与 `routers/education.py` 同理。
2. **鉴权分裂**：同一业务的端点分在两个文件，两边各写各的 `dependencies`，越权矩阵要靠全量扫描才看得出哪条漏了守卫。
3. **docstring 错位**：文件头说的是"补齐第 N 轮验收缺口"，读的人无法据此判断该往哪加代码——于是下一个人继续往里塞。

约束：**URL 不能变**（对接方与前端都在用）；54 个端点都有现成测试覆盖。

## Options（可选方案）

- **方案 A：维持现状**，在文件头补一张"这里有哪些业务"的索引。
- **方案 B：按前缀拆回既有业务文件**——`/api/tcm` 的端点移入 `routers/tcm.py`，`/api/education` 移入 `routers/education.py`，没有对应文件的（`cssd`/`maternal`/`homevisits`）各建一个。`service_extras.py` 的裸 `/api` 端点按语义归入各自业务文件。URL 与 `main.py` 的挂载顺序保持不变。
- **方案 C：只拆前缀重叠的三个**（tcm/education/performance），其余留在原文件。
- **方案 D：重写这两个文件覆盖的全部业务。**

## Advantages（各方案优点）

| 方案 | 优点 |
|---|---|
| A | 零成本零风险 |
| B | 前缀重叠与鉴权分裂一次消除；"这个业务的代码在哪"从此有唯一答案；新代码有明确的落点 |
| C | 消除最痛的一半（重叠），成本约为 B 的三分之一 |
| D | —— |

## Disadvantages（各方案缺点）

| 方案 | 缺点 |
|---|---|
| A | 索引会过期；倾倒场继续长大，下一轮验收又往里塞 |
| B | 一次搬动 54 个端点，diff 巨大不便 review；搬动期间与其它 PR 冲突面大 |
| C | 留下一半的倾倒场，判断标准变成"看情况"，下一个人不知道该不该往里加 |
| D | 违反第 2 条（不重写可运行模块）；这些业务都有测试与线上数据，重写只有损失 |

## Migration cost（迁移成本）

- **不写迁移、不动表、不动 URL**——纯文件搬家 + import 调整。
- 改动面：2 个源文件拆成约 8 个；`main.py` 的 `include_router` 清单跟着调整；测试文件的 import 路径可能要跟着改。
- 建议**按前缀分批**：一个前缀一个 PR（6 批 + service_extras 按业务再分若干批），每批 diff 可读。
- 估：每批 1-2 小时，含跑全量套件。总量约 2-3 天。

## Risk（风险）

- **主要风险是搬漏或搬错**：端点少挂一个 = 404，鉴权少搬一层 = 越权。缓解：
  - 现有的**越权矩阵扫描**（456 个写接口逐条跑越权调用）会当场抓住鉴权丢失；
  - 现有的**契约棘轮**会抓住 `response_model` 丢失；
  - 搬动前先跑一次全量并记下端点总数（881），搬完必须一致——建议加一条"端点清单零漂移"的守卫用例，把 URL 集合快照下来。
- 不做的风险：倾倒场是**会长大的**债——它已经从"第 N 轮缺口"长到 1125 行，每轮验收都往里加。

## Recommendation（建议）

采纳 **方案 B**，但**按前缀分批**落地，第一批做 `/api/performance`（它与 `routers/performance.py` 的前缀重叠最容易出事，且只有 2 个端点，是最小可验证的一批）。

落地第一步：**先加"端点 URL 集合零漂移"守卫用例**（把当前 881 个端点的 method+path 快照下来），再开始搬。没有这道网，搬漏一个端点不会有人发现。

需要后端批准；前端无需改动（URL 不变）。
