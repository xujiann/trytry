# ADR-0008：God 文件（models.py / spd/routers/config.py）分域拆包

- 状态：Proposed
- 日期：2026-08-20
- 决策者：待定（后端；`models.py` 触及全部 246 张表的 import 路径）
- 相关：`docs/模块分级_KEEP_IMPROVE_REFACTOR_REPLACE.md`（第 173 行明确判为 C 而非 D）、ADR-0001（核心表冻结）、`docs/DATA_MODEL.md`

## Problem（问题）

| 文件 | 行数 | 内容 |
|---|---|---|
| `app/models.py` | 3989 | **187 个类**，全平台 ORM 模型 |
| `app/spd/routers/config.py` | 1549 | 慢专病的全部配置类端点 |

`models.py` 的具体麻烦：

1. **找不到东西**：187 个类按"第 N 轮补全"的顺序堆叠，文件里有 `# ===== 终审轮补全模型 =====` 这种分隔——按时间而不是按业务域分区，找一张表只能靠搜索。
2. **改动冲突面大**：任何加表的 PR 都动这一个文件，并行开发必冲突。
3. **CLAUDE.md 已经在提醒"勿再无节制增长"**（§3），但没给出该往哪放——于是继续往里加。

**它不该被重写**（分级文档第 173 行已判定）：零迁移漂移、金额类型已治理、`import *` 环有测试守着。重写会破坏 246 张表的迁移历史。

约束：
- `from ..models import X` 遍布全仓（含 `app/spd/platform.py` 的适配层，边界用例盯着）；
- `models.py` 末尾 import 子系统模型，让 `Base.metadata` 认识 `spd_*` 表（`tests/test_spd_boundary.py` 的 `PLATFORM_TOUCHPOINTS` 记着这一条）；
- 核心表已冻结（ADR-0001），拆包**不得改任何列**。

## Options（可选方案）

- **方案 A：维持现状**。
- **方案 B：拆成包 `app/models/`**，按业务域分文件（`patient.py` / `clinical.py` / `pharmacy.py` / `billing.py` / `resource.py`…），`__init__.py` 重新导出全部名字，**对外 import 路径完全不变**（`from ..models import X` 照常工作）。
- **方案 C：拆成包，且要求调用方改用子模块路径**（`from ..models.patient import Patient`）。
- **方案 D：按 SQLAlchemy 的多 `Base` 拆分。**

## Advantages（各方案优点）

| 方案 | 优点 |
|---|---|
| A | 零风险 |
| B | 找得到东西；加表有明确落点；并行开发冲突面变小；**调用方一行都不用改**，边界用例与 `Base.metadata` 的行为不变 |
| C | import 路径自带业务归属信息 |
| D | —— |

## Disadvantages（各方案缺点）

| 方案 | 缺点 |
|---|---|
| A | 继续长大；CLAUDE.md 的"勿无节制增长"是一句没有落点的劝告 |
| B | `__init__.py` 要维护一份导出清单（可用 `from .patient import *` 但那会失去显式性）；分域边界要拍板一次 |
| C | 要改全仓上千处 import，diff 巨大且毫无功能收益；`spd/platform.py` 的适配层也要跟改 |
| D | 多 Base 会让 `Base.metadata.create_all` 与 alembic `target_metadata` 都要合并，收益为零、风险极高 |

## Migration cost（迁移成本）

- **不写迁移、不动表、不动任何列**——纯文件搬家。
- `models.py` → `models/` 包：按域分 8-12 个文件，`__init__.py` 显式重导出 187 个名字。
- `spd/routers/config.py` 同理按配置域拆（病种/量表/指标/路径模板/问卷/报表模板…）。
- 估：`models.py` 1-2 天（分域需要逐个类判断归属），`config.py` 半天。**建议分两个 PR，不要一起做**。

## Risk（风险）

- **漏导出一个名字 = 应用起不来**，但那是**启动即失败**，不是潜伏 bug——`make test-smoke` 与全量套件当场红。风险等级低于它看起来的样子。
- 真正要防的是**循环 import**：模型间有外键关联，按域拆容易出现 `patient` ↔ `clinical` 互相 import。缓解：关系用字符串形式（`Mapped["Patient"]`，仓库现在就是这么写的），拆包不引入新的运行期依赖。
- **迁移历史不受影响**：alembic 只认 `Base.metadata`，与模型定义在哪个文件无关。
- 建议拆前先加一条守卫：`from app.models import *` 后的名字集合快照，拆完必须一致——它能一次性证明"一个名字都没丢"。

## Recommendation（建议）

采纳 **方案 B**（拆包 + `__init__.py` 保持 import 路径不变），**否决 C**（改上千处 import 换不来任何功能收益）、**否决 D**（多 Base 收益为零风险极高）。

落地顺序：**先拆 `spd/routers/config.py`**（1549 行、影响面局限在子系统内、是很好的演练），跑通后再动 `models.py`。

第一步：加"模型名字集合零漂移"守卫用例。需要后端批准。
