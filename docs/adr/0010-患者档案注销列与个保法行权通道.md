# ADR-0010 患者档案注销列（deactivated_at）与个保法行权通道

## problem

《个人信息保护法》第 44—47 条赋予个人更正权与删除权，平台此前无任何行权
通道；而 `patients` 是冻结核心表（改列须 ADR）。医疗记录又受法定保留义务
约束，"删除权"不能实现为物理删除。

## options

A. 物理删除患者行及级联业务数据；
B. 加 `deactivated_at` 软注销列：检索与新绑定入口过滤，业务历史照常可查；
C. 不动表结构，仅登记线下流程。

## advantages

B 案：行权有系统支撑且可审计（申请→审核→变更留痕全链）；不违反医疗记录
保留义务；对冻结表的侵入只有一个可空列；历史统计口径不受影响。

## disadvantages

B 案：注销语义分散在各检索入口，需口径清单维护（已写入列注释与端点文档）；
"删除"实为停用，须向申请人如实告知口径。

## migration cost

一列可空 DateTime（迁移 e2f4a6c8b0d2，含 downgrade），存量数据零回填；
`FROZEN_CORE_COLUMNS` 快照同步更新。

## risk

过滤口径遗漏会让注销档案仍出现在检索里——已由 test_consents.py 的四面
断言钉住（检索不含 / 直取仍可 / 历史可查 / 居民端绑定 404）。

## recommendation

采用 B 案。更正白名单不含 id_card（主索引唯一键 + 实名绑定凭据，改动须
线下核验后由管理员走数据修正流程），理由写在 routers/consents.py。
