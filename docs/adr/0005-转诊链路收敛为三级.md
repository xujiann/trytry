# ADR-0005：spd 转诊链路收敛为村→乡镇→区市县三级

- 状态：Accepted
- 日期：2026-08-20
- 决策者：平台负责人（口径确认："转诊收敛为村、乡镇、区市县三级"）
- 相关：ADR-0004（分级审核按机构树 parent_id，其后续②即本决策）、
  `app/spd/routers/referral.py`（`_NEXT` 状态机）、
  回归 `tests/test_spd_flow.py`（链路/越权/存量兼容用例）

## Problem（问题）

原四级链（村医→服务站→卫生院→县级医院）的"服务站复核"档在现实数据里落不到任何
机构：`org.level` 词表只有 city/county/township/village（`platform.py:97`），机构树
实际为村→乡→县三层，测试也证明三层树下四级链只能靠全域角色代跳。ADR-0004 引入
按机构树 parent_id 的越权校验后，这个缺口从"隐性"变成"显性"（顶层接收步须全域
角色），必须决策。

## Options（可选方案）

- **方案 A（选定）**：收敛为三级——`_NEXT` 删去服务站档，新单两步审核
  （卫生院审核→县级接收）；存量在途 `station_reviewed` 单保留兼容入口按旧链续走。
- **方案 B**：补全服务站层——给机构树加第四层"服务站"机构与 level 词表。
- **方案 C**：维持现状（四级链 + 全域角色代跳第一步）。

## Advantages（各方案优点）

| 方案 | 优点 |
|---|---|
| A | 与真实机构树一致；机构账号可走完全链（已测）；改动最小（状态机两行 + 文案）；不动数据 |
| B | 保留更细的分级；与招标文件的"服务站"表述字面一致 |
| C | 零改动 |

## Disadvantages（各方案缺点）

| 方案 | 缺点 |
|---|---|
| A | 与招标文件字面表述有出入（实质满足"逐级转诊"）；前端文案需同步 |
| B | 需建服务站主数据 + level 词表（触核心表，另需 ADR）+ 存量机构定级运维；现实中多数县无独立服务站法人 |
| C | 第一步永远只能全域角色代跳，分级审核名存实亡 |

## Migration cost（迁移成本）

极小。`_NEXT` 收敛（保留 `station_reviewed` 存量兼容项）、withdraw 守卫注释、
docstring/模型注释、前端三处状态文案；无表结构变更、无数据回填。测试改 4 处断言 +
新增存量兼容回归 1 条。

## Risk（风险）

- 存量在途 `station_reviewed` 单：保留兼容入口（`_NEXT["station_reviewed"]` 按旧链
  续走、withdraw 仍可撤），新单不再产生该状态——由
  `test_referral_legacy_station_reviewed_still_advances` 钉住。
- `SpdReferralRule.handle_level` 与考核方案的 `station` 取值**不动**：那是"通知/考核
  归谁"的分类词，与链路状态机正交；收窄词表会破坏存量规则，属另案。
- 闭环率统计 `pending_by_level` 中存量 `station` 值仍可显示（前端保留该键的文案）。

## Recommendation（建议）

采纳方案 A（已实施）。同步：`_NEXT` 收敛 + 存量兼容、前端文案、测试更新、本 ADR。
ADR-0004 的后续②至此关闭。
