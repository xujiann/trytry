# ADR-0007：统计簇（analytics / metrics / reports / performance）口径合并

- 状态：**Accepted**（2026-08-21 批准）
- 日期：2026-08-20
- 决策者：待定（需产品定"同一个词算什么"，非纯技术决策）
- 相关：`docs/模块分级_KEEP_IMPROVE_REFACTOR_REPLACE.md`（C 类）、ADR-0003（三套子域）、`docs/特征化测试指引.md`

## Problem（问题）

四个文件都在做"统计"，各自定义各自的口径：

| 文件 | 行数 | 端点 | 定位 |
|---|---|---|---|
| `analytics.py` | 689 | 9 | 运营分析（床位、抗菌药强度、慢病…） |
| `metrics.py` | 517 | 5 | 驾驶舱指标 + 风险预警 |
| `reports.py` | 231 | 3 | 报表导出 |
| `performance.py` | 210 | 2 | 绩效评分卡 |

问题不是"文件多"，是**同一个业务词在四处各算一遍**。已知的分叉：

- "慢病在管人数"在 `analytics` 与 `metrics` 各有一套查询，一个按 `ChronicPatient` 计，一个按 `managed_by_org_id` 分组后求和——机构无归属的记录在两处的归属不同。
- 机构范围的解析：有的走 `deps.resolve_org_scope`（分组∩机构），有的直接 `== org_id`。
- 慢专病侧还有 `spd/reporting.py` 与 `spd/routers/assess.py` 的指标口径——ADR-0003 已记下"报表与考核必须同源"，`spd/reporting` 已经这么做了（走 `collect_metrics`），平台侧还没有。

后果：**同一个数字在驾驶舱、分析页、导出报表里对不上**，而没有任何一处说明哪个是对的。这类问题最贵的不是算错，是没人知道算错了。

约束：四个模块的响应都已被前端与对接方使用，**响应字节不能变**；口径统一意味着某些数字会变，那是**业务决策**不是重构。

## Options（可选方案）

- **方案 A：维持现状**，在文档里写明"各页口径不同"。
- **方案 B：抽共享取数层**（`app/metrics_core.py` 或 `app/services/statistics.py`），四个路由都改为调用它；**口径以哪一套为准由产品逐指标裁定**，裁定结果写进代码注释与文档。
- **方案 C：合并成一个 `statistics` 路由模块**，URL 保持不变（多个 prefix 挂在一个文件上）。
- **方案 D：以 `spd/routers/assess.collect_metrics` 的指标库为唯一取数口径**，平台侧统计全部改为引用指标库。

## Advantages（各方案优点）

| 方案 | 优点 |
|---|---|
| A | 零风险 |
| B | 口径收到一处；四个模块的职责边界不动，改动可分指标推进；哪个数字变了、为什么变，能逐条说清 |
| C | 文件少了 |
| D | 报表与考核彻底同源，与 ADR-0003 的方向一致 |

## Disadvantages（各方案缺点）

| 方案 | 缺点 |
|---|---|
| A | 分叉继续扩大；每加一个统计页就多一套口径 |
| B | 是新代码；且**每统一一个指标都要产品拍板**，推进速度取决于业务决策而不是编码 |
| C | 只搬了位置没统一口径——把四套口径塞进一个文件，反而更容易被误认为已经统一 |
| D | 指标库的取数是为考核设计的（按考核对象、按周期），运营分析要的是别的切法；强行复用会把指标库撑变形 |

## Migration cost（迁移成本）

- 不动表、不写迁移。
- 每统一一个指标：抽一个取数函数 + 改 2-4 处调用 + **补特征化网钉住当前输出** + 产品确认新口径 + 更新文档。估每指标 2-4 小时，其中一半是等口径。
- 分叉指标的清点本身就是一项工作：先出一份"同名指标在几处各算什么"的对照表，再逐条裁。

## Risk（风险）

- **统一口径必然让某些数字变**。变了就要通知用数的人，否则会被当成故障。缓解：先出对照表 → 产品逐条裁 → 改一条发一条，PR 里写清"这个数字为什么变了、变了多少"。
- 不做的风险：分叉随统计页增加而放大，最终没人敢用平台的数字对外报送。

## Recommendation（建议）

采纳 **方案 B**，**否决 C**（只搬位置不统一口径，反而制造"已经统一"的错觉）、**否决 D**（指标库为考核而设，切法不同）。

落地第一步**不是写代码，是出对照表**：把四个模块里同名/近义的指标逐个列出、写清各自的查询与差异，交产品裁定。没有这张表，抽取数层只是把四套口径搬了个位置。

需要产品 + 后端共同批准。**在对照表出来之前，本 ADR 不进入实施。**
