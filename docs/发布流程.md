# 发布流程（A6/A8）

版本发布的标准步骤：从打 tag 到验证与回滚。配套设施：

- 构建流水线：`.github/workflows/build.yml`（tag `v*` 或手动触发 → 测试门禁 → 推送 GHCR）
- 镜像：`ghcr.io/<owner>/<repo>`，标签 = git tag + 完整 commit sha（刻意不打 `latest`）
- 启动脚本：`server/start.sh`（`MEDPLAT_MIGRATE_ON_START` / `MEDPLAT_WORKERS`）
- 依赖锁定：`server/requirements.lock`（镜像与 CI 均按 lock 安装，可复现）

> **有意的边界**：流水线**只产镜像，不做自动部署**——当前没有可编程的目标部署环境
> （生产在县内网/云主机上以 docker compose 运行，Render 只是公网演示档）。
> 何时有了目标环境（如 K8s/云托管），再加部署 job 并更新本文。

## 一、发布步骤

### 1. 打 tag → 镜像产出

```bash
git checkout main && git pull
make verify                      # 本地先全绿，别把 CI 当第一道防线
git tag -a v1.4.0 -m "发布说明：为什么发这个版"
git push origin v1.4.0
```

推 tag 后 `build.yml` 自动执行：单元+冒烟测试门禁 → docker build → 推送
`ghcr.io/<owner>/<repo>:v1.4.0` 与 `:sha-<完整sha>` 两个标签。
在 GitHub Actions 页面确认流水线全绿、镜像出现在 Packages 里。

### 2. 迁移单独执行（先于新代码上线）

**多实例/滚动发布场景下，迁移不随实例启动跑**（N 个实例同时 `alembic upgrade`
会互相踩），而是发布时**单独执行一次**：

```bash
# 用新版镜像、连生产库、只跑迁移（注意是复数 heads——平台链 + spd 链双 head）
docker run --rm \
  -e MEDPLAT_DATABASE_URL="postgresql+psycopg2://…" \
  ghcr.io/<owner>/<repo>:v1.4.0 \
  alembic upgrade heads
```

单实例小站可跳过本步，保持 `MEDPLAT_MIGRATE_ON_START=1`（默认）由启动脚本代跑；
但多实例部署必须：实例统一设 `MEDPLAT_MIGRATE_ON_START=0`，迁移只在这里跑。

### 3. 滚动重启到新镜像

```bash
# compose 部署（示意）：改 image 指向新 tag 后
docker compose pull app && docker compose up -d app
# 多实例：逐实例替换，替换一个、健康一个、再下一个
```

### 4. 验证

```bash
curl -fsS https://<host>/api/health        # 200 即存活
docker compose ps                          # app 应为 healthy（镜像自带 HEALTHCHECK）
```

再抽查一条核心链路（登录 → 任一列表页）。留观 10 分钟错误日志。

## 二、回滚步骤

### 1. 回退镜像 tag

```bash
# 把 image 改回上一个已验证的 tag（这就是不打 latest 的原因：回滚目标必须明确）
docker compose up -d app   # image: ghcr.io/<owner>/<repo>:v1.3.x
```

**只回代码不回库**是首选：本仓库迁移纪律要求新列/新表向后兼容，旧代码跑在新
schema 上通常无事。先这样回，观察是否恢复。

### 2. `alembic downgrade`（仅当 schema 本身是事故原因）

```bash
docker run --rm -e MEDPLAT_DATABASE_URL="…" \
  ghcr.io/<owner>/<repo>:v1.4.0 \
  alembic downgrade <目标revision>
```

**风险，务必读完再动手**：

- downgrade 会**删表/删列，数据不可逆丢失**——降级前先备份（`server/scripts/backup.sh`）；
- 本仓库双 head（平台链 + spd 链），downgrade 是**按链**的：先 `alembic heads`
  看清楚要降哪条链、降到哪个 revision，别把另一条链一起拖下水；
- 52/52 个迁移都实现了 `downgrade()`，但生产上**极少真正执行过**——把它当最后手段，
  优先"回退镜像 + 保留新 schema"。

## 三、环境变量速查（与发布相关）

| 变量 | 默认 | 说明 |
|---|---|---|
| `MEDPLAT_MIGRATE_ON_START` | `1` | `0`=启动不跑迁移（多实例场景，迁移由本流程第 2 步单独执行） |
| `MEDPLAT_WORKERS` | `1` | `>1` 时 uvicorn 多 worker（需 Redis 在位，进程内状态不跨 worker） |
| `MEDPLAT_SEED_DEMO` | 不设 | `1` 才灌演示种子；镜像默认不带（A8），生产不要设 |

完整运行时配置见 `docs/运维手册.md` 与 `server/app/config.py`。
