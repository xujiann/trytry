## 一、结论先说：一条主线贯穿全系统

**最普遍、最严重的缺陷是同一种形态：`db.get(Model, id)` 按主键直取对象后直接读/写，绕过了清单接口已有的机构/患者隔离过滤。** 这正是本仓 `visibility.py` 注释里反复点名的 "D-8 型漏洞"——列表接口做了 `scope_org_list`/`scope_patient_list`，而同文件的 `GET /{id}` 详情或 `PATCH /{id}` 写操作漏做同源校验。它跨临床、公卫、平台、SPD 四大板块系统性复发。

在此之上，还有一条**可实际利用的自授权链**：几个"创建即产生可见性依据"的写接口缺机构校验，攻击者写一条记录就能解锁目标患者的全部档案。这是本轮最该优先修的问题。

## 二、Critical（可实际利用，优先修复）

### C1. 自授权越权链：写一条记录即解锁全患者档案 `[已核验]`

`visibility.patient_basis`（`visibility.py:230-293`）把"本机构存有该患者的就诊/签约/任意业务记录"作为最高优先级可见性依据。而下列"制造依据"的写接口**缺机构校验**：

- `routers/encounters.py:32 create_encounter` —— 未 `assert_org_writable(body.org_id)`。任何 doctor/operator 以本机构名义 POST 一条假就诊记录，即解锁该患者 360 视图/处方/结算全档案，且后续调阅留痕 `basis="encounter"` 看起来完全合法。
- `routers/patients.py:108 grant_authorization` —— 任意机构可为任意患者向任意机构签发档案调阅授权，无患者侧凭证；`revoke_authorization` 亦无归属校验。
- `routers/contracts.py:21 sign`（家医签约）—— 缺 `assert_org_writable`，签约即构成 `patient_basis` 的 `contract` 依据，等于自助开通对任意患者的调阅权。
- `routers/inpatient.py:141 create_admission` —— 未校验 `ward.org_id` 可写，可占他院床位并间接生成 Encounter 依据。

**危害**：横向越权读取全县任意患者敏感健康档案，且伪装成合法调阅。**这四个入口应作为第一批堵死。**

### C2. `is_production` 拼写即绕过 → 生产带默认密钥启动 `[已核验]`

`config.py:84`：
```python
return "prod" in (self.env, self.environment)   # 元组成员判断，需精确等于 "prod"
```
运维写 `MEDPLAT_ENV=production`（最常见写法）时 `is_production` 为 False，`_reject_default_credentials_in_prod`（config.py:86）整体失效，服务带着默认 `MEDPLAT_SECRET=dev-secret-change-in-production` 上线。JWT 密钥即 `settings.secret`（security.py:12），**可被离线伪造任意身份令牌**。这是防默认密钥的唯一闸门，被一个拼写差异静默关掉。

### C3. 跨机构篡改诊断报告并清除危急值闭环 `[已核验]`

`routers/service_extras.py:71 amend_report` 仅 `require_roles("doctor")`，`db.get(ExamReport, report_id)` 直取后即改 `conclusion/critical/critical_status`，无归属校验。乙院医生可把甲院已出的**危急报告改成"未见异常"并清空危急闭环状态**——临床安全级别的越权写。

### C4. SPD 转诊审核无机构/环节校验，且可自记积分刷奖 `[已核验]`

`spd/routers/referral.py:393 review_referral`（及 `arrive`/`down`/`receive-followup`）只校验角色不校验机构，任何服务角色可把转诊单一路推进到底并把 `current_org_id` 写成自己。`receive_followup`（referral.py:513）给**调用者本人** `user.id`/`user.org_id` 记 `referral_down` 积分（referral.py:526），可反复刷积分兑换商品。同类：`spd/routers/tasks.py` 的 claim/submit/review/complete 除 `assign` 外全无机构校验，污染绩效考核口径。

### C5. 合并财务报表全县无授权 `[已核验]`

`routers/accounting.py:324 consolidated-statements` 无角色守卫、无机构校验，仅用 `resolve_org_scope`（筛选器非授权器）。不传参即返回**全县各院合并资产负债/收入费用报表**，任何登录账号（含村医、药师）可读。同型：`accounting.py:199 vouchers/{id}`（会计凭证明细）、`quality.py:655 records/{id}`（完整病历 PHI）均为 by-id 直取无校验 `[已核验 quality/accounting 均属实]`。

## 四、Medium / Low（择要）

**并发 · 读改写丢更新**
- `pharmacy.py:405 create_stock_take` 盘点 `stock.quantity = actual_qty` 读改写，与并发入库/调拨竞争覆盖（本仓 `add_amount`/`take_amount` 注释明令禁止读改写，此处破例）。
- `prescriptions.py:252 review_prescription`、各模块 `advance` 状态推进均为 `get→判→改→commit`，无 `WHERE status=期望值` 条件 UPDATE，并发双审核/双推进都会成功。
- `main.py:437 _write_audit` 审计哈希链读 `prev` 再写无锁，多 worker 下两请求读到同一 `prev`，`verify_chain` 误报断链；且 `entry_hash` 只覆盖 `username|method|path|status`，不含 id/时间戳，插入顺序被改写不可察。`[审计链设计缺口]`
- `scheduler.py:145 tick` 无 Redis 时 `_acquire_lock` 恒 True，`uvicorn --workers>1` 下清理类/广播任务重复执行。

**规则引擎 · 统计口径漂移（SPD）**
- `spd/jobs.py:75 push_time` 无格式校验、字符串比较，配 "8:00"（未补零）则永不推送且不报错；`SpdReportTask.frequency` 在 `spd_report_push` 中**完全未被使用**，"每周推送"配置形同虚设。
- `spd/reporting.py:147 _score` 段落忽略 `org_id`，机构报告混入全域得分与排名，与"报表考核同源按机构出一份"矛盾。
- `spd/routers/referral.py:616 referrals-alerts` 用 `created_at<cutoff` 量单据年龄而非最后推进时刻，超期告警误报/漏报。

**输入校验 · 数据完整性**
- 日期字段裸 `str`：`gapfill.py:120 expire_date=""`、`followups.py:76 due_date`（仅校验长度）等，而效期/超期逻辑靠字符串字典序比较，一条脏值（"n/a"）即静默破坏预警。应统一 `DateStr`。
- `patients.py:33 id_card` 仅校验长度，无校验位，脏数据入 EMPI 去重键可致同人多档/撞号。
- `education.py:52 submit_exam` 考核分数客户端自报，可直接提交 100 分过考核。

**前端**
- `pages-spd.js:681` 病种下拉用**数组下标+1**当 `program_id`，而 `/api/spd/catalog` 返回体不含 id：id 序列有空洞时路径模板静默挂错病种或 404。`[前后端契约不匹配]`
- `pages-mgmt.js:248` 会计科目 `<option>` 未 `esc()` 直拼 innerHTML，科目名可经 API 写入含 HTML → 存储型 XSS；结合令牌存 `localStorage`（core.js:15）可窃会话。
- `pages-spd.js:246` director 页面提交 `POST /api/spd/programs`（`require_admin`）必然 403，前后端角色矩阵不一致。

**认证会话一致性**
- `ws.py:74 _token_valid` 不拒 `scope=portal` 令牌、不校验改密基线：居民端 7 天令牌可连工作人员通知通道；改密后已建 WS 长连接仍放行。
- `gmcrypto.py:172 _sm_kdf` 国密套件迭代 20k（general PBKDF2 为 120k）且为非 PBKDF2 结构，**切国密反而弱化口令存储**。
- `security.py:85 compare_digest` 对含非 ASCII 的伪造签名抛 TypeError → 500（应归一为返回 None）。

**认证主流程已核实安全**：登录有按用户名锁定（5 次/10 分钟）+ 按 IP 滑窗限速；改密/改角色置 `token_valid_from` 吊销存量令牌；`decode_token` 用定长比较校验 exp；登出按 jti 拉黑；RBAC 自定义角色命中不了任何 `require_admin` 接口，无法自授 admin；附件上传有类型白名单+10MB 限制+sha256 分桶无路径穿越；ESB/FHIR 入站有 token 鉴权。

## 五、下一步开发建议（按优先级）

### P0 · 安全整改（建议 1–2 周，阻断可利用漏洞）
1. **堵自授权链（C1）**：`create_encounter`/`create_admission`/`grant_authorization`/`contracts.sign` 一律先 `assert_org_writable(body.org_id)`；`grant_authorization` 增加患者侧凭证或限定 grantee 为本机构。
2. **修生产判定（C2）**：`is_production` 对 `env/environment` 归一化后匹配 `{"prod","production","prd"}` 集合；把 `wechat_provider=="official"` 缺 appid、生产仍为 mock/console 一并纳入启动校验。
3. **by-id 端点统一收口（C3/C5/H1–H9）**：抽 `get_owned_or_403(db, user, Model, id)` / `get_patient_visible_or_403`，替换临床/公卫/平台/SPD 全部裸 `db.get`；读侧敏感清单接 `scope_patient_list` 并留痕。
4. **金额服务端唯一权威（H11）**：`insurance.create_settlement` 按明细汇总算 total/insurance/self_pay，禁客户端自报进基金监测；`create_payment` 已付额排除退款单、自付渠道设独立上限。

### P1 · 用可检查的硬约束防复发（建议 2–3 周）
5. **CI 越权扫描**：加参数化测试——凡函数体出现 `db.get(Model, id)` 且 Model 带 `org_id`/`patient_id` 而未调 `assert_obj_org_writable`/`assert_patient_visible`/`scope_*` 的直接判红；并为本轮每处越权补一条"乙院账号访问甲院 id 期望 403"用例，纳入越权矩阵。（本仓 `test_stage14_concurrency.py` 已有同思路扫描可复用。）
6. **规则配置校验对称**：所有 PATCH（questionnaires/followup-rules/programs/indicators）与 POST 走同一 Pydantic 模型 + `validate_conditions`，杜绝"POST 校验、PATCH 裸写"；日期字段全量改 `DateStr`；`push_time` 加正则 `^([01]\d|2[0-3]):[0-5]\d$`。
7. **前端契约测试 + esc lint**：`/api/spd/catalog` 返回 `id`、表单改用 `p.id`；对全部 `innerHTML` 拼接补 `esc()` 审计（pages-mgmt.js:248 先修），加 lint 规则"模板串 `${` 后必须是 `esc(`/数字/白名单常量"。

### P2 · 并发与审计加固（建议 2 周）
8. **消除读改写**：`create_stock_take`、`review_prescription`、各 `advance` 改带 `WHERE status=期望值` 的条件 UPDATE 并校验影响行数，与既有 `take_amount`/`claim_request` 对齐。
9. **审计链加固**：`entry_hash` 纳入 id+单调序列号+`created_at`；取 `prev`+插入用 `SELECT...FOR UPDATE` 或专用单写队列；审计 MAC 密钥与 JWT 密钥分离（`settings.audit_secret`）。
10. **调度器多实例安全**：无 Redis 时也用 `UPDATE ScheduledJob SET next_run_at=... WHERE name=? AND next_run_at<=now` 判 `rowcount` 抢占式领取，真正实现单次执行。

### P3 · 会话/口径一致性收尾（建议 1 周）
11. WS 鉴权复用 HTTP 侧 `verify_access_claims`（拒 portal scope + 校验改密基线）；`_sm_kdf` 改 PBKDF2 结构并对齐迭代耗时；`compare_digest` 前对签名段做 ASCII 归一。
12. `spd/reporting.py:_score` 段落补 `org_id` 过滤；`spd_report_push` 真正消费 `frequency`；referrals-alerts 按最后一条 step 时间判超期。
