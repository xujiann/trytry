# 县域医共体信息化平台 · 全系统功能清单

本清单由**代码实际状态**生成（路由表 `app.openapi()`、页面注册表 `app/static/app.js`、
模型元数据 `Base.metadata`），不是设计稿。数字随版本变动，重新生成的方法见文末。

| 口径 | 数量 |
|---|---|
| 后端接口（操作数 / 路径数） | **879 / 673** |
| 业务域（OpenAPI 标签） | 90 |
| 数据表 | 246（其中慢专病子系统 59） |
| 管理端页面 | 87（8 个导航分组） |

# 第二部分 · 全域慢专病全流程管理系统（子系统）

依据招标文件十一端 **163 条**要求建设，逐条对照见
[全域慢专病全流程管理系统_需求对照表.md](全域慢专病全流程管理系统_需求对照表.md)。
接口 `/api/spd`（居民端 `/api/portal/spd`），共 **236 个操作**、59 张表、11 个管理端页面。
按域拆分：配置 56、服务 31、智能随访与辅助 30、人群 29、患者移动端 25、考核 24、
路径与任务 19、转诊 14、各端工作台 8。

## 一、配置域（56 个接口）

专病档案（病种）与纳入/排除规则、管理阶段与关键节点、规则版本快照；按病种与阶段的
量化目标（血压/血糖/尿酸/血氧）与定性目标、随访周期与表单；标准化指导路径模板与节点
（进入/完成条件、时限、超时处理、表单与证据要求）及新建/复制/发布/启停/删除；评估量表
（风险/阶段/康复/筛查，版本与二维码）；健康宣教素材（图文/音频/视频）；服务包；标签；
重点慢专病中心；服务团队与成员权限位；村医档案与批量开通；健康监测设备台账；
数据源接入配置与运行监控；县乡村三级机构树。

## 二、人群域（29 个接口）

机会性/主动/居民自查/数据比对四类筛查与量表评分；按纳入规则批量自动识别；高风险复核；
目标池的分发、认领、状态流转；签约建档纳管（团队、主管医生、个案管理师、村医、
知情同意、服务周期、生活习惯/危险因素/并发症）；生命周期事件（排除/迁出/死亡/召回/恢复，
跨机构迁出需目标机构确认）；召回过程留痕；患者分组（个人/科室/团队，支持自动分组规则）；
服务包绑定、解绑、项目扣减与消费台账；居民专病服务申请受理；专病 360 档案（多病种聚合）。

## 三、路径与任务域（19 个接口）

患者路径实例启动、个性化调整、节点流转与进入条件校验；统一任务中心——
路径节点/随访/干预/评估/复诊/转诊/上报/召回/宣教/筛查复核十类共用一张表，支持接收、
分配、转派、催办、超时升级、草稿保存、提交审核、审核退回、直接办结、批量处理与导出。

## 四、服务域（31 个接口）

体征与检验监测（手工/设备/院内/POCT，落库即按管理目标判等级，异常自动派处置任务）与
趋势聚合；评估执行与统计（人数/人次/结果分布/逐题分布），评估结论回写风险等级并自动
触发高危干预与复诊；干预模板与个体化干预计划（批量选人、自动建任务）；宣教推送与成效
统计；复诊计划（路径/出院/高危/手工四种来源，逾期清单与邀约留痕）；上报任务与异常上报
处置；健康处方（用药/康复/生活）；专病在线咨询与转随访。

## 五、转诊域（14 个接口）

转诊触发规则（组合诊断、检查检验、体征、风险、随访与路径异常）与命中判定；
村医 → 服务站 → 卫生院 → 县级医院逐级链路：发起、分级审核、接收、到院与**有效就诊判定**、
病情稳定下转并自动生成随访计划、下转随访接收闭环、撤回；全环节轨迹追溯；
闭环率与有效率统计（分母剔除撤回与退回）；审核超时预警。

## 六、考核域（24 个接口）

考核指标库（取数口径 + AST 白名单公式 + 评分规则三段式，版本、生效范围、使用情况查询）；
医院/卫生院/服务站/村医/团队分级考核方案；自动取数计分（八种口径：任务、纳管、路径、
转诊、监测、评估、建档、上报）与扣分明细；得分下钻至原始数据、分布与高频扣分项分析；
按机构/人员的工作量统计；村医积分（签约、有效上转、下转承接、随访完成、异常上报、签到）、
积分商品、兑换与线下核销。

## 七、智能随访服务端（通用随访能力，30 个接口含智能辅助）

随访方案规则（诊断/手术/医嘱关键词、多时间点、执行角色、科室与角色使用权限）；
结构化问卷与异常分级规则；随访任务批量生成与按患者特征自动匹配；随访前置资料聚合；
多渠道执行（电话/微信/短信/自助/上门）与失访独立状态；异常自动派处置任务；

# 附：如何重新生成本清单

```bash
cd server
python3 - <<'PY'
from collections import defaultdict
from app.main import app
spec = app.openapi(); by_tag = defaultdict(int)
for path, item in spec["paths"].items():
    for method, op in item.items():
        if method in ("get","post","put","patch","delete"):
            by_tag[(op.get("tags") or ["未分类"])[0]] += 1
print(f"标签 {len(by_tag)}  接口 {sum(by_tag.values())}  路径 {len(spec['paths'])}")
for tag, n in sorted(by_tag.items(), key=lambda kv: -kv[1]): print(f"{n:>4}  {tag}")
PY
```

页面清单取自 `app/static/app.js` 的 `PAGES` 注册表，表清单取自
`app.database.Base.metadata.tables`。
