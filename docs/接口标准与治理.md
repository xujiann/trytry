# 接口标准与治理：混乱代码 → 标准接口

```
   混乱代码（裸 dict / 无契约 / 分页各异）  ──逐块──▶  标准接口（声明契约 / 统一分页 / 向后兼容）
                                          每块先补特征化网，再动；棘轮锁住只进不退
```

881 个端点里历史上仅 ~14% 声明了响应契约（`response_model`）。本文件定义**标准接口**、
**逐块治理配方**，以及一台**棘轮**机器（`tests/test_api_contract_governance.py`）让治理
可度量、可强制、只进不退——不搞一次性大改（那违反"改动限定在任务本身"且会破坏向后兼容）。

---

## 一、标准接口（目标形态）

| 维度 | 标准 | 现状 |
|---|---|---|
| **响应契约** | 每个端点声明 `response_model`；单对象 `XxxOut`，列表 `list[XxxOut]` | 14% → 逐块补 |
| **分页** | 列表走 `deps.paginate`（`limit`/`offset` + `X-Total-Count` 头） | 44/96 文件；另有 129 个 GET 列表端点硬编码 `.limit(N)` 静默截断（两台闸门盯着，见 P2-8） |
| **错误** | `raise HTTPException(status_code, detail=...)`，响应体 `{"detail": ...}` | 已是事实标准，保持 |
| **命名** | 路径 kebab-case、集合用复数、路径参数下划线 | ✅ 已良好，勿退化 |
| **动作响应** | 新端点用规范结果体；**存量 ad-hoc 键保留**（改键名破坏客户端，属破坏性变更，需 §9 ADR） | 各自发明键名 |

> **硬约束（CLAUDE.md 第7条）**：治理**不得改变响应字节**。`response_model` 的字段必须与
> 当前输出一一对应——少声明会删字段、多声明会加字段，两者都是破坏性变更。**用特征化测试守住。**

---

## 二、逐块治理配方（每个模块照做）

1. **拿到字节基线**：优先用套件级字节捕获（见下节「取证方式」），一次覆盖所有模块；
   捕获覆盖不到的端点再手写特征化用例，钉住**当前** JSON 的键集合与取值
   （范式见 `tests/test_checkups_characterization.py`：断言"键恰好是这几个"）。
2. **加标准接口**：给缺契约的端点加 `response_model`，模型字段**精确镜像**当前输出。
   列表端点若还没分页，评估是否切 `paginate`（会加 `X-Total-Count` 头与 `limit/offset`，
   属**兼容增强**，但要确认前端不依赖"一次返回全部"）。
3. **验证字节不变**：重跑特征化网 + 该模块既有测试，全绿=行为未变。
   两类陷阱在本仓库反复出现，加契约前先照着查一遍（见下节）。
4. **下调棘轮**：把 `test_api_contract_governance.py` 里的 `BASELINE_WITHOUT_RESPONSE_MODEL`
   改小到新值，并把模块名加进 `FULLY_GOVERNED`（若已 100%）。
5. **提交**：一个模块一个提交，信息说明"混乱→标准：<模块>"。

---

## 三、棘轮如何工作（`tests/test_api_contract_governance.py`）

- `test_响应契约欠账不许变大`：断言"无 `response_model` 的端点数 ≤ 基线"。
  **新端点漏契约 → 欠账变大 → 变红**，逼着补。
- `test_已治理模块不许回退`：`FULLY_GOVERNED` 里的模块若冒出裸 dict 端点 → 变红。
- 治理使欠账变小 → 测试提示你下调基线，保持"咬得紧"。

与仓库既有"欠账不许变长"用例（`test_stage15_horizontal` 的机构归属欠账）同一手法。

## 取证方式：套件级字节捕获（推荐）

早期每治理一个模块就手写一份捕获脚本：种数据、逐个端点发请求、把响应存下来、
加契约后再跑一遍比对。做到第十几个模块时这件事本身成了瓶颈——脚本写得比契约还久，
而且每份脚本只覆盖它自己那个模块。

现在改成**给 app 装一个中间件**，把整个测试套件跑出来的每个响应按
`(方法, 路由模板, 状态码)` 记下字节，加契约前后各跑一次逐项比对。工具见
`tests/capture_plugin.py`（治理用的临时件，不进 CI）：

```bash
MEDPLAT_CAPTURE=/tmp/base.json  PYTHONPATH=tests pytest tests/ -q -p capture_plugin
# ...加契约...
MEDPLAT_CAPTURE=/tmp/after.json PYTHONPATH=tests pytest tests/ -q -p capture_plugin
# 逐 key 比对两个 json
```

一次跑覆盖全部模块（实测 1847 个「方法×路径×状态」组合），治理十个模块和治理
一个模块的取证成本一样。

**用它之前必须先量噪声底**：同一份代码跑两次，差异必须是 0。第一次实测有 2 处
（短信验证码回显、二维码随机令牌），归一化后才归零。噪声底不为 0 就开始用，
等于把自己的随机数当成「契约改坏了」，或者反过来——真差异淹没在噪声里看不见。

**它覆盖不到的**：测试套件没跑过的端点，前后都没有记录，比对自然是「一致」。
这是**沉默的缺口**，不是保证。治理时要对照模块的路由清单看哪些 key 没出现；
对没被覆盖的端点，仍需手写用例（本仓库覆盖率约 87%，缺口主要在错误分支）。

**还有一种更隐蔽的缺口：key 在捕获里，但那次调用是空的。** 列表端点返回 `[]`
时，任何契约都能通过——字段一个都没被验到，而 key 明明在捕获里，对照路由清单
是查不出来的。ADR-0006 收官批就撞到一次：`GET /api/cssd/requests` 被跑到了，
但那一次恰好没有数据。所以自查要分两步：

1. 模块的每个端点在捕获里**有没有 key**（对照路由清单）；
2. 有 key 的，那几条记录**是不是空集**（`[]` / `{}` / 只有分页壳）。

第 2 步现在还是手工看的；写用例造数据是唯一的补法——空集钉不住字段这件事，
在特征化网那边早就写过（「网里六段都造了数据——空列表什么都钉不住」），
换成套件级捕获之后它以另一种形式回来了。

**改了路由代码就要重跑**：pytest 在启动时导入 app，之后的编辑不影响正在跑的
那一次。踩过一次——加完一个模块才发现它不在刚启动的那轮捕获里，只能重跑。

## 三条「这个判断由什么决定」

治理时会遇到两类判断，别混：

- **由字节决定的**：改了声明，响应体就变——Money 的 int/float、条件键、字段顺序。
  这类必须有变异验证（改错了要能当场转红）。
- **不由字节决定的**：改了声明，响应一个字节都不变，变的是 OpenAPI 与可读性。
  实测踩到过两处：`last_sync_at` 从 `str` 改成 `str | None` 零处转红（handler 永远
  给值）；去掉 `response_class=SvgResponse` 后 content-type 照样是 `image/svg+xml`
  （返回的类自带 media_type），变的是规格书会回落成 `application/json`。
  这类的理由是「契约要诚实」，**不能拿不咬人的变异当证据**。
- **随机项不能进比对**：`token_urlsafe` 生成的令牌、时间戳，每次运行都不同。
  逐字节比对前先归一化，并做**对照实验**（同一份代码跑两次，看这一项是否也变）
  ——否则会把自己的随机数当成"契约改坏了"。

## 两个反复踩到的建模陷阱

### 陷阱一：Money 列的整数值是 `int`，声明成 `float` 就改了字节

`Money = Numeric(14, 2, asdecimal=False)`（`models/_base.py`）。整数金额读回来是
**`int`**，不是 `float`；`round(x, 2)` 作用在整数上同样返回 `int`。把这类字段声明成
`float`，Pydantic 会把 `200` 序列化成 `200.0`——账单页上的「200 元」变成「200.0 元」。

**写法**：`total_amount: int | float`（Pydantic smart union 原样透传，不做转换）。
适用于所有 `Money` 列、以及由它们 `sum()`/`round()` 派生的数值，**包括 dict 的值**
（`by_category: dict[str, int | float]`）。

**反过来也要看清**：`Float` 列（如 `spd_measurements.value`、`spd_assessments.score`）
整数值读回来就是 `140.0`，那里声明 `float` 才是原样，写 `int | float` 反而没意义。
两种列长得像，判断依据是**列类型**，不是字段名里有没有"金额"。

**怎么验**：种子数据里同时造整数与小数两种取值，逐字节比对；再把声明改回 `float`
看用例是否转红——不转红说明数据里根本没有整数值，那条用例什么也没守住。

已踩记录：`cssd.total_cost`（`0` → `0.0`）、`analytics` 多处、`portal/price-list.price`、
`portal/me/bills` 与 `/me/admissions/{id}/bill` 四处、`portal/me/deposits`（这一处是
**已经出账的 bug**，1000 元押金以 `1000.0` 返回，直到治理同一批时才被发现）。

### 陷阱二：条件键——只在某些分支出现的字段

有的键只在特定条件下出现。声明成「可选字段 + 默认值」会给**每一个**响应注入
`"key": null`：既改字节，又等于在响应体与 OpenAPI 里公告该字段存在。

**写法**：字段声明为 `X | None = None`，端点上加 `response_model_exclude_unset=True`
——handler 没放这个键，序列化时它就整个不出现（不是 `null`）。

**怎么验**：两条分支都要有用例——「出现时键在」和「不出现时键**整个不在**」。
只钉前者等于没钉，去掉 `exclude_unset` 照样绿。

已踩记录：`portal/auth/sms/code` 的 `debug_code`（登录验证码回显口子，P0 整改专门
收紧过它——契约不该把刚收紧的东西又摆回台面）、`auth/wechat/authorize` 的 `mock_code`、
`portal/me/family` 的 `member_id`（本人那一行没有它；注入 `null` 会让客户端照着调
`DELETE /me/family/None`）。

> **多态 ≠ 条件键**。同一列表里行的形状真的不同（如 `metrics/drilldown` 的八种行），
> 逐字段建模只会把各分支的字段互相注入 `null`，那时用 `list[dict[str, Any]]` 才对——
> 但要有别的东西自描述形状（`drilldown` 同响应里的 `fields` 就是行的字段清单，
> 有用例钉住两者相等），否则就是拿宽字典逃避契约。

## 非 JSON 端点（文件下载 / HTML 单据）怎么算契约

棘轮的判据是「**有 `response_model` 或显式声明了非 JSON 媒体类型**」，两者都算已声明。

**为什么不是只认 `response_model`。** 直接返回 `StreamingResponse` / `FileResponse` 的端点，
`response_model` 对它没有意义——函数不返回可序列化对象，FastAPI 也会跳过模型。
把这类端点永远算作欠账，等于往棘轮里掺一笔**永远还不掉的账**，
数字就不再表示「还有多少接口没契约」。它们的契约是「我返回 text/csv 字节流」。

**两种写法，别用错：**

| 端点实际返回 | 正确写法 | 例子 |
|---|---|---|
| 一个**字符串**，由 `response_class` 渲染 | `response_class=HTMLResponse, response_model=str` | `printing` 的 12 个 HTML 单据 |
| 一个 **Response 对象**（流式/文件） | 自带 `media_type` 的 Response 子类当 `response_class` | `reports.CsvResponse` |

第二种**不要写 `response_model=str`**：函数根本不返回 str，那是在说假话。
也**不要只写** `responses={200: {"content": {"text/csv": {}}}}`：FastAPI 会保留默认的
`application/json` 条目，OpenAPI 于是声称"这个端点可能返回 JSON"——实测如此。
让 `response_class` 自带 `media_type` 才能把默认条目去掉，
而且**声明与实际返回是同一个类**，不会两处漂开。

**这不是给自己开口子。** 判据从路由对象推导，不是手工豁免清单；
`test_放宽媒体类型口径没有白送任何端点` 钉住了"靠媒体类型脱账"的端点清单——
拿空 `responses` 刷低欠账，会让那份清单变长而当场变红。

## 五、与其它治理线的关系

- **分级**（`docs/模块分级_*.md`）：C 类模块拆分时**顺带**补契约（大模块别单独为契约动它）；
  A/B 类小模块可独立走本配方。
- **特征化测试**（`docs/特征化测试指引.md`）：本配方第 1 步就是它——契约迁移是特征化网的
  典型受益场景。
- **命名**：新测试用 `test_<模块>_characterization.py`，勿用 `test_stageN_*`。
