## 3. 强制矩阵（谁守住什么）

| 守卫（测试） | 锁住的不变量 | 基线 | 越界后果 |
|---|---|---|---|
| `test_core_data_invariants` | 核心概念=唯一权威表；身份字段单一归属 | 6 实体 / 5 标记列 | 另造核心身份即红 → 走 ADR |
| `test_schema_governance::核心表已冻结` | 核心表列集合 | 5 表快照 | 增删改列即红 → 走 ADR |
| `test_schema_governance::零漂移` | 模型表都有迁移 | 0 漏迁移 | 漏写迁移即红 |
| `test_schema_governance::双head` | 平台+spd 两分支 | =2 | 迁移拓扑乱即红 |
| `test_schema_governance::created_at` | 新表带 created_at | ≤52 | 欠账变大即红 |
| `test_api_contract_governance` | 端点声明 response_model | ≤756 | 新端点漏契约即红 |
| `test_spd_boundary` | 子系统单向依赖 + 迁移分支 | AST | 破边界即红 |
| `test_stage14_concurrency` | 写唯一约束表须处理冲突 | AST | 漏处理即红 |
| `test_stage12_dialect` | 金额定点数 / 方言 | 8 规则 | 用 Float 存金额即红 |
| `make lint` / `make typecheck` | 风格 / 类型欠账 | 8 / 41 | 新增报错即红（warning 模式接入中） |

> 棘轮的共同语义：**基线只许调小**。治理一块 → 欠账变小 → 下调基线；破坏 → 顶破基线 → 红。

## 4. 变更的"解锁流程"

碰到冻结/不可变守卫变红，不是绕过它，而是走 ADR：

1. 写 ADR（`docs/adr/`，七段：problem/options/…/recommendation）。
2. 写迁移（`downgrade()` 必须实现）。
3. 同步更新守卫的快照/白名单（`FROZEN_CORE_COLUMNS` / `IDENTITY_OWNERS` / 基线数字）。
4. 重跑 `python scripts/dump_schema.py` 刷新 `docs/schema/SCHEMA.md`。
5. 绿。

## 5. 日常怎么用

按 `docs/日常开发工作流.md` 循环：晨间（pull/CI/昨天 PR）→ 定向阅读（ROADMAP/ARCHITECTURE/AGENTS/ADR）
→ PLAN → **审批方向** → 实现（先补特征化网）→ `make verify` → `/code-review` → PR → merge。
红线：先计划后编码、架构级先 ADR、遗留先补网、绿了才往下、PR/merge 由人决定、只进不退。
