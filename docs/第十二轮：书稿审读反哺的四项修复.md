# 第十二轮：书稿审读反哺的四项修复

撰写书稿《紧密型县域医共体信息化建设》时，四路审读逐行核对"书中声明 vs
代码实现"，暴露出四条真实缺口——书里如实写了"差距"，这一轮把差距关账。
**把标准写成文字的过程，本身就是一次对实现的审计。**

## 1. 一份档案只绑一个账户：约束下沉数据库

- **缺口**：`bind_realname` 与 `_autobind_by_phone` 的"先查 taken 再绑"是
  check-then-act（与基金池 D-2 同形）。六路并发实测：同一份档案可被多个
  账户同时绑定成功。
- **修复**：`resident_accounts.patient_id` 上建部分唯一索引
  `uq_resident_account_patient`（NULL 放行、非 NULL 唯一，双方言 where），
  迁移 `d3e4f5a6b7c8` 先清重（保留 id 最小的绑定）再建索引；
  `bind_realname` 撞约束翻译成既有的 409 文案；登录自动绑定撞约束时
  登录照常、绑定让位。
- **非空洞验证**：去掉索引重跑六路并发用例，多个 200、绑定数 > 1，红；
  二路并发窗口开不稳定，压到六路才可靠触发——又一例"并发度要压到能
  触发缺陷的量级"。

## 2. 留痕统计按患者聚焦时自我留痕

- **缺口**：自我留痕的判准是"是否指向可识别的个人"，但实现只盖住了
  清单查询；`/api/access-logs/stats?patient_id=` 聚焦单人却不记。
- **修复**：stats 带 patient_id 时同样走 `_log_view`；全局聚合不记。

## 3. 病理拒收原因强制五类标准项

- **缺口**：五类标准原因只作为选项随统计接口下发，接口层收自由文本。
- **修复**：非标准项 422——拒收率要按原因分解才有管理价值。

## 4. 医废暂存点位须属同一机构

- **缺口**：store 只校验点位类型是暂存间，不校验点位归属机构，
  跨机构暂存等于把医废记到别家的暂存间头上。
- **修复**：`loc.org_id != waste.org_id` 即 422。
