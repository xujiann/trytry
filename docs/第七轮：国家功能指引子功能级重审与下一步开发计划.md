## 一、这一轮的审阅方法：把颗粒度降到子功能

前几轮的 `docs/功能指引对照表.md` 是**按 36 条主项**核对的，结论是"36 项全部
实现"。主项级的核对有个天然弱点：一条主项挂上一个模块就算实现，而指引在每条
主项后面都写了"具体功能：……"的清单，那才是验收时逐条点的东西。

这一轮把颗粒度降到子功能：从指引原文机械提取出 **36 条主项、379 条子功能**，
逐条去代码里找承载它的表与接口。判据与前几轮一致——**找不到具体的表和接口，
就不算实现**，模块名字对得上不作数。

对"完全找不到痕迹"的 54 条子功能，再回到 `models.py` 与路由逐个复核，
区分"真缺"与"换了名字"（例如指引的"资金管理"就是平台的 `/api/fund`，
"移动办公"就是已有的 H5 端）。下面的结论都经过这一步复核。

## 四、这一轮新发现的缺陷 D-4（实测确认）

### D-4 接种禁忌一旦登记即永久硬拦截，平台内无解除路径

**位置**：`app/routers/vaccination.py:39-49`

登记禁忌后，`vaccinate()` 命中即 409 拦截。问题是**绝大多数接种禁忌是暂时性的**
（发热、急性病期、近期用过免疫球蛋白），而 `vaccine_contraindications` 表既没有
有效期、也没有状态列，模块四个端点里**没有删除、没有停用、连列表查询都没有**。

**实测**：

```
登记暂时性禁忌(发热): 201
退热后再接种:        409 {'detail': '存在接种禁忌：发热(暂时)'}
平台内可用于解除的端点: ['/api/vaccination/contraindications']   ← 只有 POST
pre-check:            {'allowed': False, ...}                    ← 永久为 False
```

这个受种者此后**再也打不了这支疫苗，唯一出路是改数据库**——与 D-1 手术排班
是同一类死结。

**它还违反了平台自己的既定做法**：同样是"拦人"的黑名单，预约模块有
`DELETE /api/appointments/blacklist/{patient_id}`；到了禁忌这里却没有。
不是口味问题，是平台内部不一致。

**修法**：`VaccineContraindication` 加 `status`（active/lifted）、`valid_until`、
`lifted_by`/`lifted_at`/`lift_reason`；补 `GET /contraindications` 与
`POST /{id}/lift`。**解除要留痕不要删行**——禁忌记录本身是接种史的一部分。

### 顺带记一条较轻的：用药规则只能改不能停

`/api/prescriptions/rules` 只有 POST / GET / import，没有 DELETE 与停用标记。
录错一条规则只能靠 `import` 覆盖同 `drug_code` 的行，删不掉。
对比通用规则引擎 `/api/rules/{key}` 是有 DELETE（停用）的——又是一处内部不一致。
`DrugRule` 建议加 `active` 标记，不删行。

## 六、下一步开发计划（2026-08-12 已全部执行完毕，执行结果见文末附记）

排序原则不变：**先修会坏数据的，再补验收要点的，最后做重构。**

### 阶段九 代码健康度收口（不变，仍排第一）

在原有内容上加入本轮的 D-4：

1. **D-1 手术排班合并为单事务**；
2. **D-2 加部分唯一索引**（`sqlite_where` / `postgresql_where`）+ 并发建池回归用例；
3. **D-4 接种禁忌可解除**（加状态与有效期、补列表与解除接口、解除留痕）；
   顺带给 `DrugRule` 加 `active` 停用标记；
4. **D-3 日期校验改 `datetime.date`**，一次改掉 22 处；
5. **P0-1 N+1** 与 `dispatch_stats` 全表进内存；
6. **P0-2 统一时钟**：只留一个 `app/clock.py`，加"不得再出现裸 `datetime.utcnow()`"的扫描用例；
7. **P1-1 越权用例补到 100%**——阶段十一的入场券，量最大，可并行。

D-1/D-2/D-4 是同一类问题：**业务上"拦住"了，却没留"放开"的路**。
建议顺手立一条规矩：**任何会阻断后续业务的写操作，必须同时提供逆向操作**，
并把它加进用例（"每个 block 接口都要有对应的 unblock 用例"）。

### 阶段九·五 指引子功能补齐（新增，与阶段九并行）

第三节第 1 类的 26 条子功能。按投入产出分三批：

- **25 疫苗接种成块补齐**：`vaccine_batches`（批号/厂家/效期/剂型）、
  `cold_chain_records`（存储与转运温度、超温告警）、`aefi_reports`（AEFI 报告
  与分级、与 `vaccination_records` 关联）、接种率与 AEFI 发生率统计接口。

  而非自由文本。追溯码是指引明文点名的技术手段。
- **26 应急监测补三项**：`syndrome_monitors`（症候群）、`pathogen_monitors`

  症候群与病原监测是"多点触发预警"的两条腿，现在只有传染病病例一条。

**第三批（依赖外部或价值偏低）**

- 8 一码通与多卡协同——需省平台配合，**先只做本域一码（`ehc_no` 生成二维码
  与扫码解析），跨域主索引留接口**；
- 9 便捷寻医（出诊医生检索，依赖排班数据质量）；
- 13 名老中医经验传承、21 模拟诊疗——知识与教学类，可用现有
  `knowledge_entries` + `courses` 扩展，不新起模块；
- 24 人口及婚姻信息获取——跨部门数据接入，走 ESB，不自建；
- 31 合并报表——建议与阶段十二金额精度改造同批做，否则要改两次。

原有：角色表 + 权限点表，`require_roles` 改为查权限点；审计防篡改哈希链；

**本轮新增（来自建设模式第四条）**：

- **国密适配**：口令哈希与令牌签名支持 SM3/SM2，传输层支持国密 TLS。

- **信创数据库适配**：在达梦 / 人大金仓上跑通全量迁移与测试。

建设模式第四条明文要求灾备中心。平台侧应产出的是**可操作的方案与脚本**：

与数据库的一致性备份点。这一条不写代码也能交付一半，但不写就过不了验收。

- **不把国密写死**。做成算法适配层，默认通用算法，配置切换——
  与"地方差异走配置不走代码分支"是同一条原则。
