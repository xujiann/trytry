# 下一步开发计划（第二阶段：从演示原型到生产系统）

> 前提：第一阶段已完成功能指引36项功能的原型实现（50项测试、在线演示站）。
> 第二阶段目标：达到可在真实县域上线试点的生产标准。计划起点 2026-09，双周迭代。

## 一、优先级总览

| 优先级 | 主题 | 理由 |
|---|---|---|
| P0 | 生产化基础 | 数据不能丢、系统要稳，是一切对接的前提 |
| P0 | 安全合规 | 公网/专网部署硬门槛（等保、国密、脱敏） |
| P1 | 对接联调 | 平台价值取决于与HIS/医保/省平台的真实数据打通 |
| P1 | 实时消息 | 危急值/预警必须秒级触达，当前为刷新可见 |
| P2 | 移动端体验 | 居民端小程序化、医生移动工作台 |
| P2 | 智能化深化 | AI辅诊、需求预测，锦上添花 |

## 二、分月计划

### M1（2026-09）生产化基础 P0
- PostgreSQL 切换与 Alembic 迁移体系（初始基线 + 后续增量迁移规范）
- 配置中心化：pydantic-settings 统一环境变量，区分 dev/test/prod
- 结构化日志（JSON）+ 请求追踪ID；健康检查细化（DB连通性）
- docker-compose 一键起 app+PostgreSQL；数据备份脚本（pg_dump 定时）
- 压测基线：locust 对核心接口（登录/开单/审方）建立性能基线

### M2（2026-10）安全合规 P0
- 密码策略（复杂度、有效期、锁定）；JWT刷新令牌与登出黑名单
- 敏感字段脱敏输出（身份证/电话按角色掩码）；数据导出审批
- 速率限制（登录防爆破）；CORS/安全响应头
- 等保三级差距自评清单 → 逐项整改；国密改造技术方案（SM2/3/4选型）
- 审计日志归档与防篡改（按月归档+哈希链）

### M3-M4（2026-11 ~ 12）对接联调 P1
- 对接适配层：按《接口对接规范》实现 HL7 v2/FHIR R4 入站转换器
- HIS 对接试点：1家乡镇卫生院真实 HIS 推送患者/就诊/处方
- LIS/PACS 对接：检验结果回写、DICOM 影像链接挂载（WADO-RS 调阅）
- 医保接口沙箱联调：结算回传、转诊备案
- 电子健康卡省平台注册/校验对接（具备条件时）

### M5（2027-01）实时消息 P1
- WebSocket 通道：危急值、缺药、传染病预警实时推送到在线用户
- 站内任务待办中心：随访任务、审方队列、申领处理统一收件箱
- 短信/公众号模板消息网关抽象（对接厂商可插拔）

### M6-M7（2027-02 ~ 03）移动端体验 P2
- 居民端 H5/小程序：档案、预约、报告、宣教、满意度（复用现有API）
- 医生移动工作台：待办、移动审方、危急值确认、随访录入
- 管理端前端工程化评估：如页面复杂度继续增长，迁移 Vue3 + Vite

### M8（2027-04）智能化深化 P2
- 审方规则库扩展：相互作用、重复用药、禁忌症（对接权威知识库）
- 慢病风险预测（基于随访时序的规则+统计模型）
- 药品需求预测（用药地图 → 采购建议）
- 影像/心电 AI 初筛接口预留（对接第三方AI服务）

### M9（2027-05）试点上线
- 试点县1家牵头医院+2家乡镇卫生院真实运行
- 数据迁移工具（存量档案导入）；用户培训材料
- 上线值守与问题快速响应机制；试点评估报告

## 三、贯穿性工作

- **测试**：每模块保持测试先行，目标覆盖率≥80%；新增 Playwright E2E 冒烟集
- **CI/CD**：CI 加 lint（ruff）与覆盖率门禁；主分支自动部署演示站
- **文档**：迁移手册、运维手册、用户手册随功能同步更新

## 四、风险与应对

| 风险 | 应对 |
|---|---|
| HIS厂商配合进度不可控 | M3先做模拟器联调，规范文档化并纳入采购约束 |
| 等保测评周期长 | M2完成自评整改后立即预约测评机构，与开发并行 |
| 医保接口权限申请慢 | 提前走流程，沙箱先行 |
| 单人/小团队维护压力 | 优先自动化（迁移、备份、部署脚本），控制技术栈数量 |
