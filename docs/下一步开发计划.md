# 下一步开发计划（第三阶段：从功能完备到可以上线）

> 更新于 2026-08-24，依据 `docs/第十二轮：上线前完成度盘点与开发计划.md` 的实测。
> 上一版（第二阶段 M1~M9）的内容已全部完成或被后续十二轮工作覆盖，存档在文末附录。

## 〇、这一阶段和上一阶段的区别

第二阶段的问题是"功能够不够"。**这个问题已经解决**——第十二轮独立复测确认：
需求追溯矩阵引用的 75 个接口前缀在 730 条 OpenAPI 路径里 0 个查无此项；
86 个路由模块只有 2 个零前端引用且都合理；89 个管理端页面全部渲染 0 报错。

第三阶段的问题是**能不能上生产**。这两件事卡的东西完全不同，所以计划按
「**要不要真实环境**」而不是按业务模块分线：

- **线 A**：没有真实环境就做不了、也验不了。**是关键路径，且不由开发进度决定。**
- **线 B**：平台侧自足，可与 A 全程并行。
- **线 C**：不阻断上线，上线后做。

## 一、线 A：上线阻断项（关键路径）

> 共同点：**在开发容器里做不了**。本节给的是清单和失败信号，不是结论。
> 三样前置资源建议**立刻去要**：①一套带 WAL 归档的真 PG；②四个外部通道的
> 测试账号；③（若合同要求信创）一套国产库环境。**这三样不到位，线 B 做到
> 100% 也不能上生产。**

### A1 备份恢复演练 ⛔ 最高优先级

现状：脚本齐全（`backup.sh` / `restore.sh` / `restore_drill.sh` /
`restore_drill_pg.sh`），但**无真实 PG 演练记录**。运维手册 §4 自述
「在此之前本节只是路线，不是能力」。

| 步骤 | 验收信号 |
|---|---|
| 1. 起真 PG，开 WAL 归档 | `archive_command` 生效，归档目录有文件落地 |
| 2. `backup.sh` 全量备份 | 三处状态（库 / 附件 / 密钥指纹）同一时点，密钥本身不入包 |
| 3. `restore_drill_pg.sh` 恢复到临时实例 | `alembic current` == `heads`（**复数**，双 head）；核心表健康查询通过 |
| 4. 定点恢复 `--type=time` | PITR 语义验证通过 |
| 5. 实测归档延迟 | **拿到具体秒数**，RPO≤15min 才算达标 |
| 6. 结果记台账 | — |

**失败信号**：脚本走了 dry-run 分支却当成跑通（无 PG 时会自动转 dry-run）；
归档延迟没有实测数字只有"应该没问题"。

**之后**：季度演练一次，半年一次定点恢复。

### A2 四个外部通道联调

风险在联调不在开发——接口都留好了（`get_gateway()` / `get_wechat_provider()`）。
四条可并行，建议各自独立提交。

| 通道 | 现状 | 上线动作 | 验收信号 |
|---|---|---|---|
| 支付 | `MockGateway`（下单即 paid） | 接真网关 | 真通道是**异步**语义：下单后单据应停在 `pending`，**回调后**才转 `paid`。`payments.py` 已按异步写好 |
| 微信 | `wechat_provider="mock"` | appid/secret + 网页授权回调 | 生产响应里 `mock_code` 键**整个不出现**（不是 null） |
| 短信 | `sms_provider="console"` | 网关 + 签名报备 | `debug_code` 永不回显（已有双重门，补一条生产配置回归） |
| 外呼 | `spd_call_provider="manual"` | 外呼平台对接 | 呼叫任务下发有真实回执 |

**已有的一条硬防线不要拆**：未配置或未过出网校验时，`billing.py` **绝不静默
回落 Mock**——回落会把单据标成已支付。

### A3 PII 列加密开启

顺序不能反：

1. 跑 `scripts/pii_encrypt_backfill.py`（存量明文转密文）
2. 置 `MEDPLAT_PII_ENCRYPTION_ENABLED=true`
3. **验证等值检索**——这是最容易炸的地方

**为什么第 3 步最危险**：开态下裸写 `Model.id_card == v` **恒空且不报错**。
必须全部走 `pii_filter`，索引列比对走 `pii_index_match`。
`tests/test_pii_query_point_guard.py` 已强制（加密列清单从列类型推导，新增自动纳入），
但生产开态仍需实测一遍按身份证/手机号检索能命中。

流程详见运维手册 §12。

### A4 信创适配（若合同要求）

从未在达梦 / 人大金仓 / 麒麟上跑过。按 `docs/信创适配与备份容灾.md` §2.1 五步走，
三个已知风险点：

- 部分唯一索引 `uq_fund_pool_global`（目标库不支持带 `WHERE` 的唯一索引时，
  改为全域池写哨兵值 0 而非 NULL——替代方案已写在 `models.FundPool` 注释里）
- `batch_alter_table`（支持 `ALTER COLUMN` 的库上 alembic 自动走原生语句）
- `JSON` 列：达梦需映射 `CLOB` + JSON 约束，金仓支持 `jsonb`

**验收依据是全量 pytest 在目标库跑通**，不是"点几个页面看着没问题"；
再做一次表/列双向 diff（`Base.metadata` × `inspect(engine)`）。

> **先修文档**：该文档写"确认 186 张表"，现已 **258 张**，数字过期。

SM2/SM4 明确不自实现——接密码机，接入点是 `gmcrypto.py` 的 `mac()` / `hash_password()`。

### A5 生产配置硬化核对

生产守卫已经很硬（弱密钥 / SQLite / prod 打种子数据均**拒绝启动**）。
仍需人工确认这六项，它们**缺失时不拒启**，所以最容易漏：

| 配置 | 空值后果 |
|---|---|
| `MEDPLAT_REDIS_URL` | 登出令牌黑名单与登录防爆破锁定失效（仅告警） |
| `totp_required_roles` | 双因子未强制 |
| `clamd_address` | 附件不杀毒 |
| `alert_webhook_url` | 告警不外发 |
| `audit_anchor_webhook_url` | 审计链未锚定 |
| `session_idle_timeout_seconds` | 无空闲超时 |

**建议做成一个 `scripts/preflight_check.py`**：割接前一条命令列出所有"生产不该
是默认值"的项，避免靠人眼对环境变量表。这是本线唯一一件能在容器里先写好的事。

## 二、线 B：上线质量项（平台自足，全程并行）

### B1 契约棘轮收尾 367 → 0

**为什么算上线项而不是治理项**：39% 的端点没有 `response_model`，
OpenAPI 对这些接口等于没有规格书——外部对接方按 `/docs` 接会踩空。

一模块一提交，每批固定四步：

```
① 量本模块噪声地板（同代码跑两轮，本模块内差异必须为 0）
② 捕获基线   MEDPLAT_CAPTURE=… pytest tests/ -q -p capture_plugin
③ 加契约
④ 复捕获（--ignore 本批新用例文件）+ 按模块划范围比对 + 写用例 + 变异验证
```

批次顺序（按欠账降序）：

| 批 | 模块 | 欠账 | 备注 |
|---|---|---|---|
| 1 | `spd/population` | 29 | **两个专属坑，见下** |
| 2 | `education` | 21 | |
| 3 | `admin_mgmt` | 20 | |
| 4 | `quality` | 20 | |
| 5 | `spd/tasks` | 19 | 做完 spd 只剩 `workbench`(8) |
| 6 | `billing` | 15 | Money 陷阱密集区 |
| 7 | `inpatient` | 14 | |
| 8 | `spd/referral` | 14 | |
| 9 | `esb` | 13 | 噪声组合在这（令牌），先归一化 |
| 10 | `vaccine_supply` | 13 | |
| — | 长尾 | 余下 | `credentials`(8) `org_groups`(8) `projects`(8) `resources`(8) `spd/workbench`(8) … |

> **`spd/population` 动手前必读**
> 1. **29 个端点里 14 个在全套件里零 2xx 覆盖**（groups / candidates / recalls /
>    lifecycle-events 整片只有 403 记录）。套件级捕获对这半个模块**证明不了任何
>    事**——"前后一致"是没证据，不是有证据。用例文件要担的责任比前四批都重。
> 2. 它的噪声地板补齐前是 **4**（已随 `capture_plugin.py` 归一化补齐压回 0）。

### B2 统计口径合并（ADR-0007）

现状：只交付了 `docs/统计口径对照表.md`，摸出 **5 处口径分歧 + 1 处更严重的问题**，
合并未做。验收时会被问"同一指标四个模块算出四个数，到底哪个对"。

**注意**：`metrics` / `analytics` 的契约是刻意"只做契约不动口径"做完的——
这一步才是动口径，**不要和契约批混在一个提交里**，否则分不清"这是治理"
还是"这是改数"。

### B3 病种目录三份配置口径合并（ADR-0003 方案 C）

`chronic_disease_types` / `disease_programs` / `spd_programs` 三张表都是运营配置，
居民端看不到，**不存在"居民看到两份"的问题**——转诊读侧聚合已解决那一类。
真正的重复在配置口径：同一个 `hypertension` 码三处各带各的阈值。

### B4 `triage` 管理端入口

后端 `/api/triage/suggest` 已实现、对照表已登记、有测试，**但管理端没有入口**。
全仓唯一一条"做了没接"，工作量极小。

### B5 金额端到端 Decimal

`asdecimal=False`，Python 侧仍 float。第十一轮登记为"没有真实医保结算场景，
改了验不出对错"——**建议与 A2 支付联调同批做**，那时才有真实场景验证。

## 四、排期与依赖

```
                    ┌─ A1 备份恢复演练 ─────┐
需要真实环境         ├─ A2 四通道联调 ───────┤
（关键路径）         ├─ A3 PII 加密开启 ─────┼──→ 割接
                    ├─ A4 信创（若要求）────┤
                    └─ A5 生产配置核对 ─────┘
                              ↑
                    A5 的 preflight 脚本可先写

平台自足             B1 契约 367→0 ─ B2 口径 ─ B3 病种目录 ─ B4 triage
（全程并行）                                        B5 与 A2 同批

上线后                                          C1 … C5
```

**关键路径判断**：线 A 不由开发进度决定，由**环境到位时间**决定。
线 B 是可以持续推进的存量工作，不会成为瓶颈。因此排期的第一件事不是分配
开发工时，而是**去要那三样环境资源**。

## 五、贯穿性纪律（不变）

- `make verify` 六项全阻断，先自己跑，别把 CI 当第一道防线
- 一模块一提交；清理与功能改动分开提交
- 新功能必带测试；改 Bug 尽量带回归测试；**不得删测试凑 CI**
- 架构级变更先 ADR（七段式）
- 棘轮只进不退：契约 / 类型 / lint / `created_at` 欠账只许变小

### 优先级总览

| 优先级 | 主题 | 理由 |
|---|---|---|
| P0 | 生产化基础 | 数据不能丢、系统要稳，是一切对接的前提 |
| P0 | 安全合规 | 公网/专网部署硬门槛（等保、国密、脱敏） |
| P1 | 对接联调 | 平台价值取决于与HIS/医保/省平台的真实数据打通 |
| P1 | 实时消息 | 危急值/预警必须秒级触达，当前为刷新可见 |
| P2 | 移动端体验 | 居民端小程序化、医生移动工作台 |
| P2 | 智能化深化 | AI辅诊、需求预测，锦上添花 |

### 分月计划

**M1（2026-09）生产化基础 P0** — PostgreSQL 切换与 Alembic 迁移体系；配置中心化
（pydantic-settings，区分 dev/test/prod）；结构化日志 + 请求追踪 ID；健康检查细化；
docker-compose 一键起 app+PostgreSQL；备份脚本；locust 压测基线。

**M2（2026-10）安全合规 P0** — 密码策略；JWT 刷新令牌与登出黑名单；敏感字段按角色
脱敏；数据导出审批；登录防爆破；CORS/安全响应头；等保三级差距自评；国密改造方案；
审计日志归档与哈希链。

**M3-M4（2026-11~12）对接联调 P1** — HL7 v2/FHIR R4 入站转换器；HIS 对接试点；

**M5（2027-01）实时消息 P1** — WebSocket 推送危急值/缺药/传染病预警；统一待办收件箱；

**M6-M7（2027-02~03）移动端体验 P2** — 居民端 H5/小程序；医生移动工作台；

**M8（2027-04）智能化深化 P2** — 审方规则库扩展；慢病风险预测；药品需求预测；
