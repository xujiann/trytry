### 跨模块一致性复核

- **脱敏出口**：逐一核对所有返回患者敏感字段的出口——`patients`（检索/详情）、`integration`（HL7/FHIR 出入站回显）均统一走 `privacy.desensitize`；`archive/360`、`portal`、`todos`、WS 广播不返回证件号/电话。**未发现新泄露出口**。唯 WS 危急值广播含诊断结论全网可见（已计入 M-2）。
- **审计与 WS**：审计中间件为 HTTP 中间件，**WS 连接/断开不落审计**（当前 WS 只读推送，无写操作，可接受；若未来 WS 承载指令须补）。
- **审计粒度**：仅记 method/path/status，无资源 ID 与请求摘要，"报告修订留痕"等依赖它的声明偏弱（并入 M-6 处理）。

## 四、测试盲区（关键路径无覆盖）

1. **真实并发**：原子扣减/幂等建档均为串行模拟（约满后 409、预插冲突行），无多线程并发压测用例；L-7 的 IntegrityError→500 路径亦无测试。
2. **迁移升降级**：无自动化测试（本轮人工验证 upgrade/downgrade/re-upgrade 三段回路与 schema 一致性均通过，建议入 CI）。
3. **存量危急值**（`critical=True, critical_status=''`）的闭环行为——正是 M-1 缺陷所在的盲区。
4. **报告修订**与危急值状态交互（修订后 critical 语义）无测试。
5. **改密后旧令牌**仍有效的行为无测试（M-4 修复时补）。
6. **portal 防滥用**：双因子核验错误路径有 403 测试，但撞库/限速场景无测试。
7. `import_rules` 同批重复 drug_code、绩效指标**全停用 422** 拒绝路径、`audit/export`、`purchase-suggestions`、WS 多连接广播与断连清理均无测试。
